## 2. 我是怎么构思的

### 2.1 为什么不直接用现成回测框架（backtesting.py / backtrader / vectorbt）

1. **策略逻辑一行省不掉**：选股条件、R 定仓、持仓位约束、路径依赖出场——框架**都不管**
2. **我们要的三件事，恰恰是框架不做或不透明的**：
   - 5 个持仓位**共享一份资金**（主流框架常常是"每个标的独立跑"）
   - **按 R 定仓**（股数 = 1% ÷ 止损距离）
   - **同一根 K 线里止损与止盈都触时算哪个**（各框架默认不同，且是黑盒）
3. 该仓库有一条铁律：**「PnL 只能有一份实现」**——引入框架 = 多一条看不见的 PnL 路径

### 2.2 所以新写了一个「交易级组合模拟器」

与仓库里原有的向量化引擎是**两种模型**：

| | 原引擎 | 新模拟器 |
|---|---|---|
| 粒度 | 每根 bar 一个**目标仓位** | **成交事件**（入场/止损/止盈/出场）|
| 范围 | **单标的** | **组合**（共享资金、最多 5 笔）|
| 仓位 | `tanh(因子) × 上限`，与止损无关 | **按 R 定仓**，与止损距离挂钩 |
| 输出 | 逐 bar PnL | **逐笔交易**（含 R 倍数、出场原因）|

## 3. 我是怎么测的

数据：**1,112 个交易日 × 270 只**（2022-05-03 → 2026-10-08），成本单边 3bp。

### 3.1 记账正确性

| 手段 | 做法 | 结果 |
|---|---|---|
| **逐笔对账** | 用**独立公式**（照定义写、不复用模拟器内部任何一步）重算每一笔的 R：<br>无部分止盈：`gross=(出场−入场)×股数`，`cost=(入场×股数+出场×股数)×费率`<br>有部分止盈：两腿分别算<br>`R=(gross−cost)/(股数×(入场−初始止损))` | **171 笔全过**（含 34 笔部分止盈），最大差 **2.8e-17**；**每次跑自动核**，不符就退出 |
| **跨引擎一致性** | 在"两边都能表达"的场景（只做多/无止损/固定持有）对比原引擎 | **精确相等**（11.650485%）⇒ 是两份互校，不是两个真相 |

### 3.2 选股条件的正确性

**把 14 条条件照定义、用显式下标重写一遍**（不用 `rolling`/`shift` 那套写法），
**随机抽 3,855 个 (日, 标的) 格，逐格对比生产实现**。

结果：**逐格完全一致**。
（这个过程**抓到过一个真 bug**：条件「200MA 不向下」我当时比的是"离 200MA 的**距离**（ATR 归一）不下降"，
而不是"**200MA 本身**不下降"——两者在 **56%** 的格子上结论不同。修正后结果从 +19.00% 变成 **+4.59%**。）

### 3.3 统计公式的正确性

用**手算已知答案**的序列逐条验：最大回撤（100→120→90→130 ⇒ −25%）、
CAGR（100→121 跨 504 天 ⇒ 10%）、Sharpe（零均值 ⇒ 0）、
**beta 与 corr**（`r=2b` ⇒ beta 必须正好 2）、**剥离 beta 后还原 alpha 的 Sharpe**、盈亏比。
（这个过程也**抓到过真 bug**：`np.cov` 默认 ddof=1 而 `.var()` 默认 ddof=0 ⇒ beta 被放大 n/(n−1) 倍。）

### 3.4 因果性 / 无前视

- 信号全部 `shift(1)`（用"截至昨天"的信息）
- 入场用**次日开盘**（不用当日收盘）
- **定仓与曝险检查用"开盘价"估已有持仓**（用收盘价是前视——这条也修过）
- 出场检查**不在成交那根 bar 上做**（若按收盘成交）

### 3.5 结论的稳健性

| 手段 | 做法 |
|---|---|
| **对照臂** | 同一批入场、**同样的股数**，只换"有没有那套出场规则" |
| **随机入场对照** | 同日、同池、抽**同样多只**随机票，走**完全相同**的出场/仓位/曝险（20 次重抽）|
| **敏感性（一次只动一个）** | 止损宽度 / 止盈倍数 / 部分止盈比例 / 持仓上限 / 无进展天数 |
| **我自创参数的敏感性** | 上面 §2.3 第 7、5、1 条那三处，逐个换 |
| **分组** | 按形态 / 行业 / 出场原因 / 持有天数 |
| **逐年** | 策略 vs SPY |
| **蒙特卡洛** | **bootstrap 重采样**（不是"重排顺序"——重排不改变总和，是方法没在测东西）|
| **基准剥离** | 同时报 `beta` 与**剥离 beta 后的 IR** |
| **多重检验纪律** | 同一数据上的多个变体，若要挑"最好"的，p 值必须**一起过 BH** |

## 6. ★ 我认为**还没解决**的问题（**请重点审这里**）

### 6.1 我的"关键推断"对不对

我把**所有"盘整态"条件都改成看"截至昨天"**（而不是信号日当天）。
理由：信号日**就是突破日**，而"突破日必然动了"——若在突破日上算"紧密"，
就等于**要求突破日不动**，自相矛盾。

**这个推断你认同吗？** 有没有别的合理解释？

（实测影响：改之前 14 条全过后剩 9 格，改之后才有 552 个候选。）

### 6.2 票池的**时点性**（我怀疑这是最大的偏差，但无法从数据判断）

那个 270 只的池子据说是"从券商 App 拉的热门股"。问题是：

- 如果是「**当年**每个时点的热门股」⇒ 没有偏差
- 如果是「**今天**的热门股，回溯看过去 4 年」⇒ **带前视选择**：只看了"活到今天且今天还热门"的票

**我无法从数据判断是哪种**。但如果是后者，**结果会被系统性高估**（而现在的结论已经是"没有 alpha"）。

**你有没有办法从数据上间接检验这一点？**（例如：池子的等权买入持有收益 vs SPY，若显著超过，就是证据）

### 6.3 日线代理日内，偏在哪边

他的入场是**日内**（"开盘第一根 K 线最高点"）。我只有日线，用了两个代理：

```
次日开盘 +4.59%   ←→   当日收盘 −26.52%
```

**差 31 个百分点。** 我原以为"晚一天"会**低估**他的系统，但实测**相反**
（次日开盘通常低于当日收盘 ⇒ 我们买得更便宜）。

**这个推断（"我们的近似对他有利"）成立吗？**

### 6.4 我的结论表述是否过度或不足

我的表述是：**「无法对他的交易系统下结论」**——理由是"结果对自创参数极度敏感"。

```
【你认为我"已确定"清单里哪一条最弱，为什么】
【如果只让你改一件事，改什么】
```

每条都要说清：**问题是什么 → 为什么是问题 → 会导致什么后果 → 建议怎么改**。
