## 0. 定位与边界

### 0.1 这是什么

**一套"回测 + 验证"系统的设计基线**，回答一个问题：

> **怎么让回测结果可信，并且两年后还能重算出来？**

它包含五层，缺一层就活不过两年：

| 层 | 职责 | 不做会怎样 |
|---|---|---|
| **L1 基础层** | 配置 / 年化因子 / 版本 | 系统无法跨周期、无法复现 |
| **L2 数据准备层** | 接数据层（对齐 / 缓存由数据层给）+ 自建标签 / 复权 | 回测和实盘口径对不上 |
| **L3 回测层** | PnL / 指标 / 评分 | 指标会骗你 |
| **L4 验证层** | 样本外 / 审计 / 判定 | 发现不了自欺 |
| **L5 工程层** | 结构 / 日志 / 测试 | 半年后自己读不懂 |

### 0.2 它不是什么

- ❌ **不是 data-layer 的一部分** —— 回测是**下游**，只通过 `provide` 拿数据（承 `Agent.md` §1 接缝）
- ❌ **不是策略本身** —— 本文只规定"怎么验"，不规定"验什么策略"
- ❌ **不是一次性脚本** —— 本文所有约束都以"两年后还能用"为验收前提

### 0.3 与 data-layer 的接缝

```
回测系统  ──（只通过 provide 契约）──►  data-layer/
```

provide **实际暴露**的（`data-layer/provide/api.py` + `cli.py`）：`days` / `symbols` / `items` /
`get` / `matrix` / `timeseries` / `panel` / `export`。**没有** `chain` / `kline` / `snapshot` 这类专用入口。

| 拿什么 | 怎么拿 | 说明 |
|---|---|---|
| 交易日清单 | `provide.cli days` | 库里有数据的交易日 |
| 横截面指标 | `provide.cli matrix --day <D> --items <...>` | 批量 |
| 跨日序列 | `provide.cli timeseries --symbol <S> --item <I>` | |
| 底层数据（自算） | `provide.cli get --day <D> --symbol <S> --item chain`（或 `kline`） | 键 = `(日, 标的, chain/kline)`，走通用 `get`；**不是专用方法** |

**回测系统不许**知道 `store/` `fetch/` `engine/` 的实现（承 P2）。

> ✅ **多品种对齐已接入 provide**（承 §2 D1）：
> 命令行 `provide.cli align --symbols <S...> --item kline [--min-bars N]`，
> 同进程 `Access.align_panel(symbols, item="kline")`。
> 回测**只调 provide**，不碰 `engine`；对齐不在这里自建。
> 另：`snapshot` / `watchlist` **未入库**，provide 拿不到（要用得先入 `store`）。

### 0.4 最高目标（不可违背）

> **回测结果可信，且两年后能逐位重算。**

四条硬要求：

| 要求 | 意味着 |
|---|---|
| **可复现** | 两年前的结论，今天用同样输入能重算出同样结果 |
| **可扩展** | 换品种 / 换周期 / 换市场，不用重写回测代码 |
| **防自欺** | 结果不是幻觉 —— 不靠"好看的曲线"骗自己 |
| **可维护** | 半年后回来，能读懂、能改、敢改 |

**验收判据（写死）**：

> 拿一个**全新的策略**，不用改回测系统的任何一行代码，
> 能跑出**可信的**结论，并且**知道该不该信它**。
> 能 ✅ ｜ 不能 ❌（= 回测系统本身有问题）

## 1. L1 基础层（地基 —— 决定系统能否跨周期）

> **上层可以重写，地基不能。** 这一层做错，后面全白做。

### 1.1 陷阱（先看会怎么死）

| # | 陷阱 | 翻车形态 |
|---|---|---|
| B-A | **年化因子写死** | 写死 `6240`（外汇 H1）→ 换日线数据 Sharpe 被放大 26× |
| B-B | **成本率多处硬编码** | 训练用 `0.0001`、回测用 `0.0003` → 评分误判高 Sharpe |
| B-C | **训练门槛 = 实盘门槛** | 训练要 3000 根，实盘只给 800 根 → 永远算不出信号 |
| B-D | **无版本标记** | 特征表加了一个字段，旧策略静默按新口径跑，你以为在复现 |

### 1.2 约束

| # | 约束 | 可验证标准 | 来源 |
|---|---|---|---|
| **B1** | **唯一配置源** —— 成本率 / 阈值 / 窗口，**全系统只在一处定义** | 全仓 grep `0.0003` → 只在 config 出现一次；其余引用变量 | AlphaMaster `config.py:139-145` |
| **B2** | **年化因子自动估计**，禁止按周期写死 | 同一策略在 H1/D1/15min 上 Sharpe 量级一致，不随周期缩放 | AlphaMaster `backtest.py:33-120` |
| **B3** | **版本锁定** —— 任何影响结果的输入变动 → 版本哈希变 → 旧产物拒绝加载 | 改一个特征名 → 旧策略加载**抛错**，不静默 | AlphaMaster `vocab.py:48-100` |
| **B4** | **训练门槛与实盘门槛解耦** —— 两个独立常量 | 改训练 `MIN_BARS` 不影响实盘 `REALTIME_MIN_BARS` | AlphaMaster `vm_rolling_zscore_fix...md:33-37` |
| **B5** | **WF 的 `gap` 按预测周期标定**，不写死 | 换周期（H1→D1）时 `gap` 被重新评估；`gap ≥ horizon` | AlphaMaster `model_core/config.py:137-145`（P2-6） |

### 1.3 B2 详解（最关键的一条）

**问题**：不同市场、不同周期，每年 bar 数完全不同。

```
A股日线   ≈ 244  bar/年
外汇 H1   = 6240 bar/年
加密日线  = 365  bar/年
A股 15min ≈ 3904 bar/年
```

**若写死 `6240`**：
- 用 A股日线 → Sharpe 被**放大 26 倍**
- 用 15min → Sharpe 被**缩小 0.4 倍**

**解法**：从时间戳序列**直接估计**。

```
years_span = (t_last - t_first) / (365.25 × 86400)
periods_per_year = T / years_span          # T = bar 数
periods_per_year = clamp(round(ppy), 10, 600000)   # 上下限保护
```

**两个实现细节**（AlphaMaster `backtest.py:90-105`）：

1. **多品种取中位数** —— 避免单一品种异常值污染
2. **失败必须显式告警** —— 不许静默回退到 `6240`：

```
"[警告] estimate_periods_per_year: 时间戳无效或不足，回退到默认 H1=6240。"
```

**为什么必须显式**：静默回退会让 D1 数据被按 H1 年化，**Sharpe 放大 26 倍而无人知晓**（承 P1）。

**验证标准**：
```bash
# B2-a：H1 数据 → ppy ≈ 6240
# B2-b：D1 数据 → ppy ≈ 244~365
# B2-c：缺时间戳 → 打印警告，不静默
# B2-d：同一策略跨三个周期跑 → 年化量级同阶
```

### 1.4 B3 详解（可复现性的地基）

**做法**：给"任何影响结果的输入"打**内容哈希**。

```
VERSION = "v" + sha256("\n".join(sorted_inputs)).hexdigest()[:12]

sorted_inputs = [特征列表, 算子列表, 归一化窗口, 成本率, 代码commit]
```

**性质**（AlphaMaster `vocab.py:53-55`）：

> 相同的有序列表 → 相同版本；任意组成或顺序变化 → 不同版本。

**加载时校验**，不匹配直接拒绝：

```
对得上 → 加载
对不上 → 报错「版本不匹配：产物 {V} != 当前 {V'}，需重算」
```

**为什么这是地基**：两年后你看到策略表现变了，**第一件事是确认"口径有没有变"**。没有版本锁，你无法区分"策略失效"和"口径漂移"。

### 1.5 B5 详解（gap 不是常数，要按预测周期标定）

**WF 的 `gap` 不是随便取的数** —— 它必须按**预测周期（horizon）**标定。

AlphaMaster `model_core/config.py:137-145`：

```
# P2-6 修复说明：gap 必须按 target_horizon 标定，且与 CPCV purge gap 统一。
# 当前 target_horizon=2（data_manager 用 log(open[t+2]/open[t+1]) 作 target_ret），
# gap=20 相当于 10 个「真实预测步」——对 H1 数据足够，但若切换到 D1/15min
# 需要重新评估。CPCV 模式（未实现）的 purge gap 应等于 WF_GAP，避免两套阈值。
# 调整时同时检查：
#   1. engine.py _build_walk_forward_folds 的 val_start = train_end + gap
#   2. fold_size 应 >> gap（建议 fold_size >= 5*gap）以保证 val 有效性
WF_GAP: int = 20
```

**三个要点**：

| # | 要点 | 为什么 |
|---|---|---|
| 1 | `gap ≥ horizon` | 否则训练段末尾的**标签**会"看到"验证段（标签本身是未来收益） |
| 2 | 按"预测步数"而非"bar 数"理解 | `gap=20` 在 `horizon=2` 时 = 10 个真实预测步 |
| 3 | `fold_size >= 5 * gap` | 否则 val 段太短，统计无意义 |

**换周期必须重估** —— 从 H1 切到 D1，同一个 `gap=20` 覆盖的**真实时间**完全变了。

**验证标准**：
```bash
# B5：把 gap 改成 0 → 构造"训练段末尾标签泄漏"场景，检测应能识别差异
# B5：horizon 改成 5 时，gap 必须 ≥ 5（否则报错）
```

## 2. L2 数据准备层（接数据层 + 自建标签/复权）

### 2.1 陷阱

| # | 陷阱 | 翻车形态 |
|---|---|---|
| D-A | **多品种时间轴用并集 + ffill** | 造出假 K 线（`close==open==high==low`）→ 波动率特征全污染 |
| D-B | **用 `bfill` 补数据** | 用未来价格填过去 → 未来函数 |
| D-C | **标签用 `close[t] → close[t+1]`** | 收盘瞬间无法成交 → 半个 bar 的虚假收益 |
| D-D | **每次重拉全量数据** | 两年数据每次重拉 → 慢到无法迭代 |
| D-E | **股票用不复权价算收益** | 除权除息日出现假暴跌 → 标签全是噪声 |
| D-F | **回测自己另定一套时间戳口径** | 与数据层（Unix 秒 + 美东）不一致 → 对齐错位 |
| D-G | **时间戳单位错（秒/毫秒/秒÷1000）** | 能读进来但日期变 1970 年 → **静默**全错 |
| D-H | **用前复权（qfq）做回测** | qfq 锚定最新，含未来除权信息 → 未来函数 |
| D-I | **复权因子直接拿噪声值用** | 比值带量化噪声 → 每根 bar 抖动 |
| D-J | **停牌复牌被误判为除权** | 长期停牌复牌的合法跳空 → 误当除权，历史价整体放大 |
| D-K | **重叠事件被当独立样本** | 持有期内相邻触发日的收益**互相重叠**、同日 N 个信号被当 N 次独立实验 → `n` 系统性虚高（futu 实测：4,076 笔只落在 **992 天**，按笔 vs 按日**符号翻转**） |

### 2.2 约束

**先分清归属**（承最高目标"数据只有一份"）：属于数据层的**只消费、不重建**，只有"用途特有"的才自建。

| 归谁 | 内容 |
|---|---|
| **数据层提供**（回测只消费） | 时间戳口径（Unix 秒 + 美东）、多品种对齐（交集）、本地缓存 + 增量 |
| **回测层自建**（用途特有） | 标签 `target_ret`、复权换算（用数据层的 raw + `adjust_factor`） |

| # | 约束 | 可验证标准 | 来源 |
|---|---|---|---|
| **D1** | **多品种对齐用交集**，不用并集 —— **消费数据层，不重建** | 对齐后**无** `close==open==high==low` 的假 bar | AlphaMaster `data_manager.py:201-262`；数据层 `engine/time_alignment.py` |
| **D2** | **标签 = `log(open[t+2] / open[t+1])`** | 边界最后两根置 0；用 `open` 不用 `close` | AlphaMaster `data_manager.py:306-330` |
| **D3** | **只允许 `ffill`，禁止 `bfill`** —— 数据层已保证"缺就不补" | 数据层无 `bfill`；回测不自行补数 | AlphaMaster `data_manager.py:246-248` |
| **D4** | **本地缓存 + 增量更新** —— **消费数据层** | 第二次跑同一区间 → 不重复联网 | 数据层 `store` + `run_kline` |

| **D6** | **时区口径由数据层保证**（Unix 秒 + 美东），回测**不重新定义** | 回测时间戳与数据层一致 | `Agent.md` §4.4 |
| **D7** | **时间戳做量级校验** —— 单位错（秒/毫秒/秒÷1000）要**报错**，不静默修 | 时间戳落在合理区间；越界 → 报错或显形修正 | AlphaMaster `parquet_manager.py:180-188` |

### 2.3 D1 详解

> ★ **这一条数据层已经做了，且已接入 provide**：`provide.cli align --symbols <S...> --item kline`
> （或同进程 `Access.align_panel`）。回测**只调 provide** 即可，**不要自己再写一份**。
> 下面保留原理，是为了让你**看懂它为什么对**。

**为什么用交集**（AlphaMaster `data_manager.py:203-207`）：

> 使用交集而非并集：只保留所有品种都有真实报价的时间戳，
> 彻底消除因休市 forward-fill 导致的"重复K线"问题。

| 方案 | 后果 |
|---|---|
| **并集 + ffill** | 外汇休市时美股开盘 → ffill 造出假 bar → 相关性/波动率特征被污染 |
| **交集** | 只保留所有品种都有真实报价的 bar → 杜绝假数据 |

**降级策略也要有**：交集太小（< `MIN_BARS`）才退回并集，**但只用 `ffill`**：

```
# 仅使用 ffill（因果填充），禁止 bfill 以避免未来信息泄漏
reindexed = reindexed.ffill()
```

**事件去重（D12，2026-10-06 补 —— 债 TD-05-4）**：

对齐解决了"**跨品种**同日聚集"，但**事件级**统计还差一刀：持有期 20 天时，
**相邻触发日的收益互相重叠**；同日 N 个信号若被当 N 次独立实验，`n` 会系统性虚高。

⇒ 事件统计前先按 `gap >= 持有期` 去重（同位置 = 同日多信号 ⇒ 压成 1 个），
并**报「样本 n」时同时报有效簇数**。唯一实现 = `backtest/panel_statistics.py::dedupe_overlapping_events`。

### 2.4 D2 详解（最容易错的一行）

**目标收益的定义**：

```
target_ret[t] = log(open[t+2] / open[t+1])
```

**为什么是 `t+1 → t+2` 而不是 `t → t+1`**：

```
你看到 t 收盘 → 决策 → 实际成交在 t+1 开盘
                                ↓
                 收益从 t+1 开盘算到 t+2 开盘
```

**用 `close[t] → close[t+1]` 是错的** —— 你在 `close[t]` 时**无法成交**。这半个 bar 的差异，在高频策略上就是生与死。

**边界处理**：最后两个位置（`t = T-2, T-1`）置 0。

**验证标准**：
```bash
# D1：对齐后无"四价相等"的假 bar
# D2：人造一段已知数据 → target_ret 逐位等于手算
# D3：grep 数据层 → 无 bfill
# D4：连跑两次 → 第二次 0 次网络请求
```

### 2.5 D5 详解（复权 —— 股票回测的必答题）

> AlphaMaster 只做**期货 / 外汇**，没有除权除息，所以它没有这一条。
> **我们做股票，必须处理** —— 这是数据层"四问"里明确交给下游的一环。

**数据层给的是**：K线 = **不复权（raw）** + `adjust_factor`（每个除权日一行）。数据层**不替你选口径**。

**回测要做的**：算 `target_ret` 前，先把价**换算成同一条复权口径**，否则：

```
除权除息日：raw 价"凭空"跳一档（分红/拆股）
         → log(open[t+2]/open[t+1]) 里混入一个假跳变
         → 标签全是噪声，模型学的是"除权"不是"行情"
```

**两种正确做法**（择一，别混）：
1. **自算复权价**：用 `adjust_factor` 把 raw 序列调成前复权 / 后复权，再算收益；
2. **除权日修正**：在除权日按因子调整相邻两根的比价。

**注意**：全市场回测里，**每只都要按自己的除权日调**，不能只调你手里的那几只。

**验证标准**：
```bash
# D5：取一只在区间内有除权的股票 → 复权后收益曲线在除权日无假跳变
# D5：对同一只，raw 算出的 target_ret 与复权算出的，在除权日必须不同
```

### 2.6 D7–D11 详解（复权口径是本次补充最重要的一条）

> 来源：`Detect_support_and_resistance_levels`（A股项目，`src/srlab/`）——
> 它把"复权"这件事做到了工程级严谨，值得整段吸收。

**D7: 时间戳单位错是静默故障**

AlphaMaster `data_pipeline/parquet_manager.py:180-188`：

```
# 兼容性修复：某些 A 股 parquet 导出工具把 Unix 秒时间戳误存为
# "秒/1000"（数值被缩小 1000 倍，导致日期变成 1970 年）。
# 若最大时间戳 < 1e7（1970-04-27 之前），则视为被除过 1000，乘回。
if pd.api.types.is_numeric_dtype(sub["time"]) and sub["time"].max() < 10_000_000:
    sub["time"] = sub["time"] * 1000
```

**教训**：单位错的数据**能读进来**（是数字），但日期全错。**必须做量级校验**，越界要显形（报错或带日志修正），不能静默。

**D8: 回测必须用后复权（hfq）—— qfq 偷看未来**

`Detect.../srlab/adjust.py:160-179`：

```
mode='qfq' 前复权（锚定最新一根）
    factor[t] = prod(ratio[d] for d in 除权日 if d > t)
    => 最新一根 factor == 1.0，最新价保持真实市价，适合界面展示。
    **但它不是因果的**：t 时刻的因子取决于 t 之后发生的除权。

mode='hfq' 后复权（锚定第一根）
    factor[t] = prod(1/ratio[d] for d in 除权日 if d <= t)
    => 第一根 factor == 1.0，t 时刻的因子只依赖 <= t 的事件，**严格因果**。
    回测必须用这个。
```

**这是最隐蔽的未来函数之一**：前复权看起来"方便"（最新价 = 真实市价），但 **t 时刻的复权因子包含了 t 之后才发生的除权**。用它做回测，等于让策略提前知道未来的分红送转。

**口径分工**：**回测用 hfq（因果），界面展示用 qfq（好看）**。

**D9: 尺度不变性（让"用哪种口径"变得不重要）**

`Detect.../srlab/leakage.py:42-53`：

```
后复权(严格因果) 与 前复权(锚定最新，含未来除权信息) 只差一个全局常数，
而本算法以 ATR 为尺度，因此检测结果的**相对几何**必须完全一致。
...
如果它通过，说明用哪种口径回测都不影响结论，
而后复权是严格因果的，所以回测选它。
```

**这是一个可自动化验证的性质**：把算法设计成"**以 ATR 为单位**"（而非绝对价位），则 hfq/qfq 只差全局常数 → **结论一致** → 你可以放心用因果的 hfq 做回测。

**D10: 停牌复牌过滤**

`Detect.../srlab/adjust.py:123-127`：

```
误判防护
    停牌复牌可能合法跳空超过涨跌幅上限，因此**跳过距上一根 K 线
    超过 max_halt_days 个自然日的 bar**（长期停牌复牌，不是除权）。
    只识别向下跳空：A股 缩股极罕见，向上大缺口更可能是复牌或脏数据，
    误当除权会把历史价格整体放大，危害更大。
```

**D11: 复权因子是分段常数（去噪）**

`Detect.../srlab/adjust.py:338-342`：

```
两个序列都是 2 位小数，比值带 ~0.1% 的量化噪声，直接用会在每根 bar 上引入抖动。
真实因子是**分段常数**的，因此按 step_thr 检测阶跃点，段内取中位数，
还原成干净的阶梯函数。
```

**验证标准**：
```bash

# D8：grep 回测代码 → 只用 hfq，不出现 qfq
# D9：hfq 与 qfq 各跑一遍 → 相对几何逐点一致
# D10：有长期停牌的标的 → 复牌跳空不被当作除权
# D11：因子序列的阶跃数 << bar 数（是阶梯，不是锯齿）
```

### 3.3 R1 详解（PnL 唯一公式）

```
position = tanh(factor)                        # 仓位封顶 ±1
prev_pos = roll(position, 1); prev_pos[0] = 0  # 用上一根算换手
turnover = abs(position - prev_pos)
pnl = position * target_ret - turnover * cost_rate
```

**四行，每行都有坑**：

| 行 | 作用 | 不做会怎样 |
|---|---|---|
| `tanh(factor)` | 仓位封顶 ±1 | 直接用 factor 当仓位 → 可能开 100 倍仓 |
| `roll(1)` | 用**上一根**仓位算换手 | 用当前仓位算当前换手 → **未来函数** |
| `prev_pos[0] = 0` | 首根无前值，视为空仓 | 不处理 → `roll` 把最后一根绕到第一根 |
| `turnover * cost` | 换手成本 | **只算持仓成本 → 高频策略虚高** |

### 3.4 R2 详解（Sortino 分母地板 —— 必须做）

**问题**（AlphaMaster `backtest.py:153-154` 注释）：

> P0b 修复：下行标准差地板改为全序列 std 的 20%，防止稀疏 PnL 靠极小分母刷高分。
> 原来 `floor=|mean_pnl|` 对稀疏序列趋近于零，导致 Sortino 爆炸。

**场景**：策略只在上涨时交易，下跌时几乎空仓 → **下行标准差趋近 0** → `mean / ~0` = 天文数字。

**修法**：

```
full_std     = std(pnl)                    # 全序列标准差
floor        = max(full_std * 0.2, eps)    # 地板 = 全序列 std 的 20%
downside_std = max(std(亏损部分), floor)   # 分母加地板
sortino      = mean / downside_std * sqrt(ppy)
```

**这个坑几乎所有自写回测都会踩。** 不修，你的指标会系统性骗你。

### 3.5 R3 详解（年化别多除）

**正确**（AlphaMaster `backtest.py:524-526` 注释）：

> `pnl.mean()` 已是单 bar 平均收益，因此年化只乘每年 bar 数；
> **不能再除以样本长度。**

```
ann_ret = pnl.mean() * periods_per_year     # 对
# ann_ret = pnl.mean() * ppy / T            # 错（多除 T）
```

### 3.6 R4 详解（评分不要只用 Sharpe）

AlphaMaster 的评分演进值得抄（`backtest.py:511-515`）：

> 核心改变：加入年化绝对收益项（权重 0.40），这是最主要的优化目标。
> Sortino/Calmar 权重大幅下调，仅作为风险调整辅助。

**建议权重**：

| 维度 | 建议权重 | 为什么 |
|---|---|---|
| 年化收益 | 0.40–0.60 | 主目标，但要配其他项防刷分 |
| 风险调整（Sortino/Calmar） | 0.10–0.20 | 单看收益会奖励高波动 |
| OOS 一致性 | 0.10 | 前 80% 好、后 20% 崩 = 过拟合 |
| 成本压力 | 0.05–0.10 | 成本翻倍还活着 |
| 品种/时段一致性 | 0.05–0.10 | 防"3 个品种只有 1 个赚钱" |

### 3.7 R5 详解（换手 / 暴露控制）

三个惩罚项（`backtest.py:287-402`），各有分工：

| 项 | 罚什么 | 设计哲学 |
|---|---|---|
| `_turnover_quality` | 交易频率偏离目标 | 每天约 1 笔为最优，环形打分 |
| `_turnover_penalty` | 换手率过高 | 梯度惩罚 |
| `_exposure_penalty` | **只罚"太懒"** | 极稀疏（<10% 在场）才罚 |

**`_exposure_penalty` 的设计值得注意**（`backtest.py:383-386`）：

> 在场时间惩罚（仅下限，无上限）：收益优先模式。
> 只惩罚极稀疏交易（<10%在场），不惩罚高在场时间。
> 高在场时间（满仓趋势跟踪）是外汇市场最赚钱的形态之一，不应受罚。

**它只罚"太懒"，不罚"太勤"（勤的由换手率罚）** —— 有 trade-off 意识。

**验证标准**：
```bash

# R2：构造稀疏 PnL → Sortino 有界，不发散
# R3：恒定收益率数据 → 年化 = 收益率 × ppy（手算对齐）
# R4：评分函数含 ≥ 5 个维度
# R5：高频策略 → 换手惩罚显形；极稀疏 → 暴露惩罚显形
```

### 3.8 R6–R13 详解（"退化状态"是系统性偏差的温床）

> 这八条是**同一个主题**：当数据处于**边界或退化状态**（开头、无波动、常数窗口、极端值）时，
> **朴素计算会输出"假的强信号"**。必须**显式识别 + 输出中性值**，而不是让公式自然算出一个数。
> 来源：AlphaMaster 特征/算子层的一批修复（P1-6 / P1-8 / P2-11~P2-15）。

**R6: 统计量跨切片 = 泄漏**

`model_core/engine.py:556-563`：

```
P1-6 修复：相关性只在 train 切片上计算，避免含 val 段数据泄漏。
```

**教训**：**任何"用到了整段数据"的统计量都是泄漏源** —— 相关性、分位数、标准化参数、因子池去重……只要它跨了 train/val 边界，就是泄漏。**凡计算，先问"用了哪一段"。**

**R7: warm-up 期的 pad 0 污染归一化**

`model_core/features.py:144-148`：

```
【P1-8 修复】：warm-up 期（t<w-1）窗口中 pad 0 占多数，导致 med=0、
MAD=1e-6，输出被强制 clamp 到 ±_CLIP_BOUND（±5）常数——前 199 bar
的所有 _norm() 特征都是 ±5 常数，IC 计算失真。修复：warm-up 期
输出 0（中性值），等窗口填满后再用真实 median/MAD 归一化。
```

**教训**：滚动窗口 warm-up 期，**必须输出中性值（0）**，不能输出"用 pad 算出来的值"。否则**开头一段全是常数**，会污染 IC/相关性等统计。

**R8: 算子首值输出常数**

`model_core/ops.py:49-51`：

```
P2-12 修复：t=0 时 mean=x[0]、z=0，输出恒为 tanh(-1.5)≈-0.905（与输入无关），
前几个 bar 输出几乎是常数，作为因子起点会引入系统性偏差。修复：warm-up 期
（t < min_warmup，默认 5）输出 0（中性），等累积足够样本后再用真实 zscore。
```

**R9: 系数未归一化 → 幅度放大**

`model_core/ops.py:72-75`：

```
P2-11 修复：原系数和=2.4 未归一化，输出幅度是输入的 2.4 倍，可能放大下游
tanh 饱和。改为归一化（除以系数和），与 _op_wma 语义一致。
```

**R10: 同类算子边界语义必须一致**

`model_core/ops.py:181-184`：

```
P1-12 修复：原实现用 (w <= cur) 包含当前值自身，值域 [1/d, 1]；与
_ts_rank (w < cur) 严格小于、值域 [0, (d-1)/d] 语义不一致。统一为
严格小于，使两算子在边界值上行为一致，避免公式搜索选错"恢复算子"。
```

**教训**：`<=` 与 `<` 的不一致，会让**同类算子的值域不同** → 搜索/组合时选错。

**R11: 状态量初始化无方向偏见**

`model_core/features.py:1126-1129`：

```
P2-15 修复：原 direction 初始化为 +1（多头偏见），下跌市场初期需等到
首次 close < prev_lower 才翻转，前若干 bar 误报为多头。
改为初始化 0（中性），直到首次突破才确定方向。
```

**教训**：**任何"状态/方向"量，初值必须是中性（0），不能是 +1** —— 否则开头一段有系统性多头偏见。

**R12: 无信息状态必须输出中性**

`model_core/features.py:499-503`：

```
P2-13: high==low（休市/无波动）时 (close-open)/eps 是巨大值，被 clamp
到 ±1 暗示强买压/卖压——实际是无信息状态。修复：检测 high-low < eps
时输出 0（中性），避免无信息极值污染因子。
```

**R13: 常数窗口的伪信号**

`model_core/features.py:1227-1231`：

```
P2-14: 常数窗口（R=0、S=0，如盘整期无波动）下 log(0+eps)≈-13.8，
clamp 到 0 后映射到 -1（强信号），污染因子。修复：检测 R 或 S 过小
时输出 0.5（Hurst 中性值），映射为 0（中性）。
```

**统一模式**（这八条的共同解法）：

```
检测退化条件 → 输出中性值（0 / 0.5）→ 不要让它自然算出一个数
```

**验证标准**：
```bash
# R6：相关性计算传入 train_slice → 断言不含 val 段数据
# R7：前 199 根特征 ≠ ±5 常数（应为 0）
# R8：算子 t=0 输出 = 0（不是固定常数）
# R9：算子输出幅度与输入同阶（和=1）
# R10：两同类算子在边界值上行为一致
# R11：方向量前 N 根 = 0（不是 +1）
# R12：构造 high==low → 输出 0（不是 ±1）
# R13：构造常数窗口 → 输出 0（不是 -1）
```

### 4.4 V1 详解（独立审计 —— 最不能省的一条）

**核心原则**（`rigorous_backtest_audit.py:1-6`）：

> 不复用训练 reward；判决只用 PnL + 硬规则。

**为什么**：如果审计用的**目标函数**和训练搜索用的是同一个，那么"训练时钻的评分空子"在审计时会**再次被钻**，你永远发现不了。

**必须分离的是"目标"，不是"实现"**：
- 训练侧：用于**搜索**（可以有惩罚项、门控、启发式）
- 审计侧：用于**判决**（只有纯粹的 PnL + 硬判定）

**★ 关于"共享 PnL 函数"（易错点，2026-10-06 更正）**：

- **PnL 公式全系统唯一（R1）→ 生产路径必须共享。** 两个生产实现 = **两个真相**，
  判决失去基准 —— 这比"共同盲区"更糟。
- 但**共享不产生独立性**：同一个函数**不能自证**（拿 `pnl_series` 去验 `pnl_series` 恒真）。
- ⇒ **独立证据必须来自"带外"**：
  1. **手算期望值**的已知答案测试（期望值手推，**不来自**被测函数）；
  2. **污染未来测试**（V9）：把 `t` 之后换成垃圾，断言 `[0..t]` 逐位不变；
  3. （可选）测试里放**朴素参考实现**做交叉验证 —— **绝不进生产路径**。
- ⚠️ 只共享、不补带外证据 → 共享 PnL 里的**未来函数 / 算错**，搜索与审计**同时被骗**
  （= 测不出来 / 测出来是错的）。

**验证标准**：
```bash

# V2：构造已知泄漏场景 → 带 gap 的 WF 能检出，不带 gap 的检出不了

# V4：成本翻倍 → 判定结果随之变化

```

### 4.5 V2 详解（WF 的 gap）

**时间序列滑动窗口折天然存在边界泄漏**：

```
折 1: [train ... | val]
折 2:      [train ... | val]      ← 折 2 的 train 覆盖了折 1 的 val 区间
```

若特征有 20 期回看窗口，**折 2 的 train 里就包含了折 1 的 val 数据** → `val_score` 不再是干净样本外。

**`gap=20` 在折之间插隔离带**，让前面的 val 永不被后面的 train 看到。

**多数人用 `sklearn.TimeSeriesSplit`，它不带 gap。** 这个细节把可信度拉高一个档次。

### 4.6 V7 详解（物理防泄漏 —— 最强的手段）

> 来源：`Detect_support_and_resistance_levels/src/srlab/walkforward.py:5-12`

```
结构性防泄漏
------------
    ctx.high = sym.high[:t+1]      <- numpy 视图，检测器**物理上拿不到** t 之后的数据
    评测函数则只读 sym.*[t+1 : t+horizon]
```

**这是防泄漏的最强形式** —— 不是"约定不要看未来"（代码纪律），而是**把未来数据从内存里切掉**（数据结构），让检测器**物理上无法访问**。

| 手段 | 强度 | 问题 |
|---|---|---|
| 注释写"严格因果" | 弱 | 纪律会被人（或未来的自己）违反 |
| **切片隔离（`[:t+1]`）** | **强** | 想违规也没有数据可拿 |

**推论**：回测引擎的接口设计，应当**只把 `<= t` 的数据传进决策函数**，而不是"传全量 + 靠自觉"。

### 4.7 V8 详解（因果枢轴 —— 天生带未来的指标怎么办）

`Detect.../srlab/pivots.py:5-16`：

```
为什么需要"确认时刻"(confirm_idx)：
    传统 ZigZag / fractal 枢轴天生带未来信息 —— 判定第 i 根是摆动高点，
    需要看到 i 之后价格回落了足够幅度。如果直接把枢轴喂给 t 时刻的检测器，
    就会用到未来信息，回测结果全部作废。

本模块的做法：
    对整条序列**一次性**跑 O(n) 的 ZigZag，但为每个枢轴记录它被确认的
    那一根 bar 的下标 confirm_idx（即价格反向走出 k*ATR 的那一刻）。
    t 时刻只允许使用 confirm_idx <= t 的枢轴 —— 这与"在 t 时刻实时计算"
    的结果完全等价，但省掉了 O(n^2) 的重复计算。
```

**教训**：**有些指标天生需要未来数据才能定义**（ZigZag 枢轴、分形枢轴、局部极值）。

**不能简单禁用它们**（它们有信息价值），而应：
1. 一次性算出全部，同时记录**确认时刻** `confirm_idx`
2. `t` 时刻**只放行 `confirm_idx <= t` 的**
3. 用测试验证"等价于在 t 时刻实时重算"

**验证**（`leakage.py:143-164`）：全序列 zigzag + `confirm_idx` 过滤 == 在截断序列上重算 zigzag，逐点比对 `idx` / `price` / `kind` / `confirm_idx`。

### 4.8 V9 详解（污染未来测试 —— 因果性的终极检验）

`Detect.../srlab/leakage.py:168-171`：

```
把 t 之后的所有 bar 替换成随机垃圾，重算 ATR/枢轴后在同一个 t 上检测。
任何检测器如果偷看了未来，输出必然改变。
```

实现（`leakage.py:184-209`）：把 `t+1..n` 的 OHLCV **全部替换成随机值**（价格乘 0.2~5.0 的随机系数、成交量乘 0.1~10.0），重算 ATR/枢轴，**断言检测器输出逐位不变**。

**这是 §5.3「因果性测试」的最强形式**：

| 弱形式 | 强形式（本条） |
|---|---|
| 末尾追加一点未来数据，看结论变不变 | **把未来全部换成垃圾**，看结论变不变 |

**越彻底的污染，越能暴露隐蔽的泄漏。**

### 4.9 V10 详解（placebo 对照 —— 最震撼的一条）

`Detect.../srlab/walkforward.py:41-47`：

```
冒烟测试暴露的问题：placebo_fixed 把关键位机械地放在 ±1.5/2.5/4.0 ATR，
几何中位误差 0.69 ATR，反而**优于** V2 的 1.18 ATR。原因不是它更聪明，
而是未来 40 根内的摆动极值绝大多数就落在 1~4 ATR 这个区间，
它均匀铺满了这个区间，而 V2 会把位放到 0.2 ATR 或 7 ATR 处。
因此必须把所有检测器约束到同一个距离带，"命中率"才反映定位能力
而不是距离分布的巧合。
```

**这是本次补充里最震撼的一条**：

> **一个"机械地把位置铺在固定距离上"的假基线（placebo），打败了"聪明"的模型。**

`metrics.py:6-8` 把它上升为原则：

```
原则：
  1. 任何比例都配 Wilson 置信区间与样本量，禁止裸比例；
  2. 任何"胜率"都必须有对照组（placebo）才有意义 —— 支撑位在均值回复的
     市场里天然有较高的"守住率"，不与对照比就是自欺；
  3. 提升度差异做两比例 z 检验，给出 p 值。
```

**教训**：**任何指标必须和 dummy baseline 比**。如果你的"智能算法"打不过"均匀铺位 / 固定阈值 / 随机信号"，那它没有价值。

**推论**：回测系统必须内置几个**假基线**（placebo），和真实策略一起跑。

### 4.10 V11 详解（混杂因子控制 —— 别把"放得远"误判为"算得准"）

`Detect.../srlab/metrics.py:283-292`：

```
为什么必须分层比较
    实测（test 集）: 阻力位的守住率随距离从 68.4%(0.84 ATR) 升到 84.9%(4.2 ATR)，
    +16.5pp，是所有因子里最强的主效应。
    因此"某检测器守住率更高"完全可能只是因为它偏爱把位放得更远。
    要回答"算法是否真的知道关键位在哪"，必须在**同一距离档内**比较。

CMH 检验正是为此设计：把样本按距离分层，每层构造 2x2 表
(检测器 x 守住/突破)，再合并各层的证据，得到"控制距离后"的统一结论。
```

**教训**：**当存在一个强主效应（这里是"距离"）时，跨组直接比较会被它主导。** 必须**分层**（Cochran–Mantel–Haenszel）后再比较，并用 MH 合并优势比。

**推广**：你的策略指标（Sharpe / 胜率）也一定被某些"结构性因素"主导（波动率、距离、持有期）。**比较前先分层。**

### 4.11 V12–V17 详解（统计严谨性打包）

**V12: 禁止裸比例 —— 本仓口径 = 簇级区间**

> 任何比例都配区间与样本量，禁止裸比例。
> ⚠️ **本仓修正（2026-10-06，债 TD-05-1）**：原条款写「配 **Wilson** 区间」。Wilson 由二项分布推出，**隐含「观测独立」**，而本仓面板**不满足**（见下反例）⇒ 区间**系统性偏窄**，会放行假阳性。

**为什么不能直接用 Wilson**（同一批信号，两种算法，结论相反）：

| 口径 | n | Wilson 95% 区间 | 判决 |
| --- | --- | --- | --- |
| 天真：n = 品种数 | 200 | **[53.1%, 66.5%]** | ✅ 显著优于 50% |
| 真实：只来自 5 个交易日 | 5 | **[23.1%, 88.2%]** | ❌ 跨过 50%，什么都不显著 |

> **区间宽度靠 `1/√n` 缩小，但只有独立观测才能贡献这个缩小** ——
> 把同一个信息重复 200 遍，不会让你多知道 200 倍。

**本仓工具（唯一实现 = `backtest/panel_statistics.py`，纯标准库、零 IO）**：

| 函数 | 用途 |
| --- | --- |
| `clustered_interval(...)` | **默认口径**：簇级 bootstrap 区间（重采样**簇**，不重采样单条） |
| `effective_sample_size(...)` | 报 `n` 时**同时给簇数** —— 两者差距大就是预警 |
| `clustered_cmh(...)` | V11 分层比较（分层维度 = 交易日，见 §4.10b）；**只产出 `p_value`，不提供判决** |
| `wilson_interval(...)` | **仅限簇内单序列**（如单一品种逐笔胜率）；用于面板 ⇒ 判错 |
| `benjamini_hochberg(...)` | **V18**：报 p 值的**唯一判决出口**（结果自带 `family_size`） |
| `dedupe_overlapping_events(...)` | **D12**：事件去重（`gap >= 持有期`），重叠触发只算 1 次 |

**报比例的硬格式**（V12 的验收判据）：

```
胜率 60.0% [簇级 95%: 23.1%, 88.2%]   n=200 观测 / 5 簇
                ↑ 不是 60% [53.1%, 66.5%]  ← 那是把 5 份信息当 200 份
```

⚠️ **`n` 与「簇数」差距越大越危险**：差距接近 1（簇数≈n）时 Wilson 可用；差距大时**必须**用 `clustered_interval`。

**"模型说 70% 是不是真的 70%？"** —— 可靠性表让用户直接验证：

```
预测概率分箱 → 对比每箱的预测均值 vs 实际守住率
```

```
# 必须用 close[j]，不能用区间边沿。
# 原因：触及的定义就是 low[j] <= zone.high，所以"以 zone.high 为进场价"时，
# MAE 天然有一个 >= (zone.high - low[j]) 的正下限，而 MFE 没有对称下限，
# 于是 edge = MFE - MAE 被结构性地压成负数（冒烟测试中全体检测器 edge_atr
# 均为负，就是这个偏差造成的）。
# close[j] 是 A股 T+1 下真正可成交的价格，且对多空对称、无构造性偏差。
```

**教训**：**评测的基准价选择会引入构造性偏差。** 用"区间边沿"当进场价 → MAE 有正下限、MFE 没有 → `edge` 恒为负。**必须用真实可成交价。**

**V17: 校准必须样本外**（`metrics.py:186-190`）

```
保序回归校准（PAVA 自实现，避免引入 sklearn 依赖）。
在 train 股票池上 fit，在 test 股票池上 predict，杜绝校准本身过拟合。
```

**教训**：**校准器本身也会过拟合** —— 在 train 上 fit、test 上 predict。

**V18: 禁止裸 p 值 —— 必须报分母（2026-10-06 补，债 TD-05-2）**

> ⚠️ 原条款只要求"每个比例带区间"，**漏了 p 值**。而 p 值比比例更危险：
> 比例至少还报了个 `n`，p 值连"试了几次"都不说。

```
策略注册表（strategy_contract）+ 阈值网格（backtest_config）⇒ 必然试 N 次
1 − 0.95¹⁸ ≈ **60%**     ← 试 18 次，至少一次假阳性的概率
```

> **只报单个 p<0.05 而不报分母，等于没做统计。**

| | 控制 | 代价 |
| --- | --- | --- |
| Bonferroni | 至少一次假阳性的概率（FWER） | **太保守**，检验一多就什么都不显著 |
| **BH（本仓）** | 假阳性占「发现」的比例（FDR） | 平衡 —— **探索性研究该用它** |

**本仓工具**：`statistics.py::benjamini_hochberg` —— 返回 `MultipleTestResult`
（自带 `family_size`，判决与分母**绑死**）。`clustered_cmh` **只产出 `p_value`、不提供判决**
（已删掉裸判的 `is_significant()`）。

**验证标准**：
```bash
# V7：决策函数只接收 [:t+1] 切片 → 想拿未来也拿不到
# V8：全序列枢轴+confirm_idx == 截断重算（逐点一致）
# V9：污染 t 之后 → 输出逐位不变
# V10：placebo 与真策略一起跑 → 有对照数据
# V11：按距离分层后比较 → 输出各档 lift + CMH p 值
# V12：每个比例都带 [lo95, hi95] 和 n
# V18：报 p 值必报检验次数 → 判决只经 benjamini_hochberg（无裸判出口）
# D12：事件统计前去重 → dedupe_overlapping_events(gap >= 持有期)
# V13：宽度分层报告 + width_capped 口径
# V14：从下方碰到"支撑" → result == no_touch
# V15：区内盘整 20 天 → 只计 1 次触及
# V16：进场价 = close[j]（不是区间边沿）
# V17：校准器 fit/predict 的样本池不重叠
```

### 5.3 测试策略

**优先测这三类**：

| 类型 | 测什么 | 例子 |

| **边界** | 空 / 单 bar / 全零 / NaN | 不崩、不静默 |

### 5.5 E5–E8 详解（让系统"两年后还在正确运行"）

**E5: train-serve skew（训练与实盘走了两条代码路径）**

`model_core/ops.py:150-154`：

```
P1-10 修复：统一使用 exact 递推路径，避免训练时 T 大走 vectorized 卷积近似、
实盘时 T 小走 exact 递推导致的 train-serve skew（虽然 max|Δ|<1e-4，但会
通过 MACD_HIST/PPO/TRIX_15/EMA_RATIO_12_26/TREND_STRENGTH_50/SUPERTREND_DIR/
SAR_DIST 等特征传播，在 tanh 阈值附近可能改变方向判定）。
```

**教训**：**同一个指标，训练和实盘走了两条不同的实现路径**（一个近似、一个精确），差值虽小（<1e-4），但会通过下游特征**传播放大**、在阈值附近**翻转方向**。

**解法**：**统一走一条路径**（哪怕慢一点）。性能损失（实测 N=1, T=10000 下 < 5ms）远小于口径不一致的代价。

**E6: 原子写入**

`model_core/engine.py:1200-1213`：

```
P1-3 修复：原子写入（tmp + os.replace），避免 Ctrl+C / OOM 打断写入
导致 history 文件损坏。异常打印告警而非静默吞掉。
```

**教训**：**任何落盘（策略、检查点、曲线、状态）都要原子写**：

```
写 tmp 文件 → os.replace(tmp, 目标)   # POSIX/Windows 均原子
```

中断时要么是旧值、要么是新值，**绝不会是半截**。而且**异常必须打印告警**，不能静默吞掉（否则掩盖磁盘满/权限错误）。

**E7: 注释承诺 ≠ 代码行为**

`model_core/island_engine.py:121-125`：

```
# 同步全局最优到每个 island 的 best_snapshot
# 这样下次 restart 时可以从全局最优恢复，而非局部最优
# P1-2 修复：同时同步 _best_snapshot，否则 restart 时加载的仍是
# island 局部 snapshot，而非全局最优——与注释承诺不符。
```

**教训**：注释说"从全局最优恢复"，但代码只同步了 `best_score`/`best_formula`，**没同步 `_best_snapshot`** → restart 时恢复的其实是**局部最优**。

**这类"注释与实现不符"的 bug 极难发现** —— 因为注释让你相信它是对的。**凡是注释承诺的行为，都要有测试覆盖。**

**E8: 特征计算缓存**

`data_pipeline/single_symbol_manager.py:66-71`：

```
P2-16 修复：缓存计算结果，避免每次访问都重算 65 个特征。
AlphaEngine 训练时每步访问一次 feat_tensor，原本每次都要重新计算
30+ 个 rolling/expanding 统计量，浪费 CPU。数据加载后 raw_dict 不变，
特征输出是确定性的，缓存一次即可。如需刷新，调用 invalidate_cache()。
```

**教训**：**训练循环里的重复计算是性能杀手。** 数据不变 + 计算确定性 → 缓存一次，并提供显式失效接口。

**验证标准**：
```bash
# E5：同一指标在 T=100 / T=10000 下输出一致（无近似路径分叉）
# E6：写入中途 kill → 磁盘上无半截文件；异常有告警
# E7：模拟 restart → 恢复的是全局最优（有测试断言）
# E8：连续访问 feat_tensor → 第二次 0 次重算
```
