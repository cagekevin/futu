## 一、定位（State 1）

| 维度 | 内容 |
|---|---|
| **做什么** | 回答一句话：**某个「选择规则」挑出来的股票，后续表现是否系统性地优于随机？** |
| **给谁用** | ① 你自己（判断「11.5 的筛选器」「板块轮动」这类规则值不值得信）；② 后续目标 2、3、4 复用同一套对照 |
| **核心价值** | 补上现有系统**缺失的那一半判据**——「换成随机对照，它还成立吗」 |
| **不做什么** | 不取数、不做时序回测与 PnL、不产生「策略收益」、不做组合权重优化、不下单、**不做 UI** |

**为什么需要它（不可替代性）**：

现有 `factor-layer/evaluate/` 能回答「**这个因子值有没有排序能力**」（RankIC / ICIR / 分组单调性），
但**回答不了**「**这套筛选规则选出来的那批股票，后续表现是否优于随机**」。两者失效模式不同：

| 问法 | 现有能力 | 缺口 |
|---|---|---|
| 因子值越大 → 后续收益越高？ | ✅ RankIC / 分组单调性 | — |
| 按规则筛出的 K 只 → 是否优于同日随机 K 只？ | ❌ | **本文件要补的** |

**依据**：`../关于策略/10-测试-机器层验证目标.md` 目标 1 明确写
「这是机器层里**唯一『能测』的核心声称**」；`../关于策略/2-世界-视频整理.md` 第 2 章给出门槛
——「**任何声称有规律的东西，至少要先跑赢猴子**」（1,000 只猴子的对照实验：真实策略只跑赢 83%，即每 6 只猴子里有 1 只更好）。

**与已有各层的边界**：

| 层 | 它负责 | 本能力的关系 |
|---|---|---|
| `data-layer/` | 原始事实 | **上游**，只经 `provide` 契约取数 |
| `factor-layer/` M1–M5 | 面板 / 暴露 / 因子 / 预处理 / 因子评估 | **复用 M1 的面板与票池**；**复用 M5 的标签**（`forward_return`）；**新增本能力** |
| `backtest/` | 单标的 × 时间序列的严格验证（含 V10 placebo 的**时序**版） | **并列下游，互不 import**（承 01-PRD §二） |
| `frontend/` | 展示（当前为空） | 无关系（**本阶段不做 UI**） |

**最高目标（不可违背）**：

> **任何「选择规则」，都能在这里用一套固定流程回答「它是否优于同日随机」，且结论可复算、可复核。**

**「可回答」验收判据**：

> 给你一个从没见过的筛选规则，能不能**不改任何代码**（只加一个规则文件 + 一行登记）
> 就跑出完整对照报告？
> 能 ✅ ｜ 不能 ❌（= 流程没抽象对）

### 额外检查

**① 三个模块之间真的不重叠吗？**

| 检查对 | 结论 |
|---|---|
| R1 vs R2 | ✅ 不重叠。R1 只产「**名单**」（不知道有随机这回事）；R2 只产「**随机名单**」（不知道哪一边是真实） |
| R2 vs R3 | ✅ 不重叠。R2 只**造零分布**；R3 只**算数**（不做任何抽样） |
| R1 vs R3 | ✅ 不重叠。R1 在**进去之前**（给名单），R3 在**出来之后**（算判决） |
| R1 vs M3 `factor/` | ✅ **不重叠**。M3 产「**因子值**」（连续、可排序）；R1 产「**选中/未选中**」（0/1 决策）。**一个是原料，一个是决定** |
| R3 vs M5 `metrics/` | ✅ 不重叠。M5 算「**IC / 分组单调性**」（因子值 vs 未来收益）；R3 算「**配对差值 vs 零分布**」（名单 vs 随机名单）。**问法不同** |
| R3 vs `backtest/statistics.py` | ⚠️ **有一处形式相似**（都涉及抽样）但不重复：`statistics.py` 的 `clustered_interval` 是「**对已有观测做 bootstrap 区间**」；R2 是「**在票池内直接构造零假设的抽样分布**」。**方法不同、输入不同** ⇒ 不复用（且承 E1/E2：本层本就不 import 它） |

**什么时候用哪个（写死，防混用）**：

| 你要回答的问题 | 用哪个 |
|---|---|
| 「这个比例 / 胜率的**置信区间**是多少？」（**已有观测**的不确定性）| `backtest/statistics.py::clustered_interval` |
| 「这个**选择规则**的成绩，是不是比随机好？」（**构造零假设**）| **本能力（R2 + R3）** |

两者**不互相替代**：前者估「已知样本的不确定性」，后者回答「这套规则**有没有信息**」。
本能力**不 import** 前者（承 E1/E2 + C1）。

**② 与 `backtest/` 的边界（必须写进 `Agent.md`）**

| # | 边界 | 说明 |
|---|---|---|
| **B1** | 两者都做 placebo，但**形状相反** | `backtest` 的 V10 placebo 是**时序**（策略信号 vs 随机信号）；本能力是**截面**（选中的 K 只 vs 随机 K 只）。**同一判据，两种切法，不是重复** |
| **B2** | 产物不同 | `backtest` 出「策略 INVALID/SUSPICIOUS」；本能力出「**选中集 vs 随机集的配对差值 + 百分位**」。**不许互相冒充** |
| **B3** | 交接方式 | 若将来要串起来，只经「**候选池文件**」（承 01-PRD §二）——**不 import** |

## 三、陷阱（State 3）

| # | 陷阱 | 翻车形态 | 为什么危险 |
|---|---|---|---|
| **T1** | **跨日比较** | 把「真实的 K 只」和「**其他日子**随机抽的 K 只」比 | 同一天所有股票**一起涨跌**——跨天比，比的是「牛市那天」和「熊市那天」，不是选股能力。**这是本能力最容易翻车的地方** |
| **T2** | **数量不一致** | 真实选 10 只，陪考抽 50 只 | 选得越多越接近「平均」，两者**不可比**。唯一变量必须是「**选哪 K 只**」 |
| **T3** | **票池用错** | 用**全局票池**（全部历史标的）而不是**该日票池**去抽 | 前视偏差：抽到「那天还没上市/已退市」的股票。承 01-PRD **Q2** |
| **T4** | **样本量不显形** | 只报「超出随机 +3%」，不报「只有 12 天有效」 | 12 天的结论和 1,000 天的结论**同写一行** ⇒ 读者无法判断可信度。承 **P5** |
| **T5** | **调阈值刷「通过」** | 设一条「百分位 > 95% = 通过」的线，跑不通过就降线 | 门槛一旦可调，就变成**过拟合的另一种形式**。承 `../关于策略/3-认识-思维误区.md`「先写规则，再看结果」 |
| **T6** | **抽不满却静默继续** | 某日票池只剩 3 只，却仍按 K=10 抽 | 造出「重复抽同一只」的假分布，**且不报错**。承 **P6** |
| **T7** | **成本口径漂移** | 抽样用免费、真实用扣费（或反过来） | 两边不同口径 ⇒ 结论无意义。承 **Q4**（口径消耗必填） |

## 四、约束（State 4）

### 跨模块约束（锚定后续一切细化）

| # | 约束 | 可验证标准 |
|---|---|---|
| **C1** | **单一取数入口** | 只走 `provide` 契约取数；**禁止 import `data-layer` 的 `store/` `fetch/` `engine/`**；**禁止 import `backtest/`**。`grep placebo/ 的 import → 无 store/fetch/engine/backtest` |
| **C2** | **票池按日切片** | 抽样**只在该日票池内**进行；票池取自 M1 的 `universe_by_day`（**不自建、不用全局票池**）。构造「全局票池」场景 → 报错或显形告警 |
| **C3** | **口径消耗必填（无默认）** | 抽样次数 / 随机种子 / 成本率 / 成本口径 / 分档切点，**全部必填**。不传任一 → 报错（承 **Q4**） |
| **C4** | **判决必须预注册**：三档规则（**通过 / 说不清 / 不通过**）**写进契约、参数冻结**（见 §6.4）；报告记下冻结时刻。**禁止**在契约之外临时调阈值 | 三档阈值**只出现在一处**（配置常量）；改动它 → 测试红；报告含 `verdict` 与 `rule_frozen_at` |
| **C5** | **判决必过多重检验** | 若报告含 p 值，**必须**一次 BH 校正整批，且**报检验次数**；无「拿单个 p 值直接下结论」的出口（承 **Q5**、backtest V18） |

### 各模块核心约束

| 模块 | 约束 | 可验证标准 |
|---|---|---|
| **R1 选择集** | **H4**：**派生边界** —— R1 可基于**已声明的因子**做「**该日可见**」的派生（差分 / 比较 / 布尔组合），但**不得引入新的面板字段、不得重算原始指标**（RSI 本体归 M3）| `grep placebo/ → 无原始指标公式`；构造「R1 内自算 RSI」→ 代码级检查**红** |

| **R3 配对判决** | **Z1**：**同日配对** —— 逐日算 `真实[t] − 陪考[t]`，**禁止跨日池化** | 结果只由**同日配对**产生；跨日构造 → 报错 |
| | **Z2**：**三道判据必须都报** —— ① vs 随机对照 ② 前后半段 ③ 扣成本 | 报告缺任一项 → 报错（承 `../关于策略/10-测试-…` §三） |
| | **Z3**：**成本显式传入**，无默认；真实与陪考**同一成本口径** | 不传成本 → 报错；两侧成本率不同 → 报错 |
| | **Z4**：**样本量必须显形** —— 报告含有效天数、每日 K、票池中位数，**并附幸存者偏差告警** | 报告缺任一 → 报错；告警取自 M1 的 `universe_diagnostics` |
| | **Z5**：**复用唯一标签** —— 只用 `evaluate/forward_return.py`，不另写 | `grep → 无第二处 `log(open[t+2]/open[t+1])`` |

## 五、第 2 层：模块细化（五步法）

> 每个模块走一遍五步法（边界对齐 → 拆解结构 → 识别陷阱 → 设计路径 → 汇总确认）。

### R1 选择集（selection）—— 已细化

**边界对齐（State 1）**

> 职责：**定义「选择规则」的唯一接口与注册表：给定某一天，返回当天选中的股票集合。**

| 校验对象 | 结论 |

## 六、地基级固化（定死 vs 留白）

### 6.1 配对设计（**定死**）

```
对每个交易日 t：
    real[t]      = 真实选中集 S_t 的 forward_return 平均
    null[t][r]   = 同日随机抽 |S_t| 只的 forward_return 平均      r = 1..R
    delta[t]     = real[t] − mean_r(null[t][r])

判决只建立在 { delta[t] } 之上（同日配对 ⇒ 日期效应自动消掉）
```

**为什么必须配对**（承 T1）：同一天所有股票共享同一次市场冲击。
跨日池化会把「市场涨跌」混进「选股能力」。

### 6.2 报告字段（**定死，缺一即报错**）

| 字段 | 含义 |
|---|---|
| `n_days` / `n_days_valid` | 总天数 / 有效天数（两侧都有值） |
| `k_per_day_median` | 每日选中数的中位数 |
| `universe_median` | 每日票池规模的中位数 |
| `real_mean` | 真实侧平均收益 |
| `null_mean` | 陪考侧平均收益 |
| `delta_mean` / `delta_median` | ★ **配对差值的均值 / 中位数** |
| `rank_percentile` | ★ **真实落在零分布的第几百分位**（判决的输入）|
| `win_days_ratio` | **胜率**：跑赢陪考的天数占比（**描述统计，不作门槛**）|
| `verdict` | ★ **三档判决**（通过 / 说不清 / 不通过，规则见 §6.4）|
| `first_half_delta` / `second_half_delta` | 前后半段的配对差值 |
| `cost_rate` / **`real_mean_after_cost`** / `null_mean_after_cost` | 成本率（显式传入）/ **真实侧**与陪考侧**各自**扣往返成本后的平均收益 |
| `survivorship_warning` | 幸存者偏差告警文本（来自 M1 诊断） |
| `rule_frozen_at` | 规则的预注册时刻（承 T5） |

### 6.4 判决规则（**定死，看结果之前写死**）

> 这是 C4 的落地：**规则在此冻结**，跑出来什么样就是什么样。
> 对应的量见 §6.2（`rank_percentile` / `first_half_delta` / `second_half_delta` / `delta_after_cost`）。

| 档 | 条件（三条**同时**看）|
|---|---|
| **通过** | ① `rank_percentile` **≥ 95%** ② 前半段与后半段的配对差值**都为正** ③ **`real_mean_after_cost` 为正**（真实侧扣成本后仍赚钱）|
| **说不清** | 上述 3 条**满足 1–2 条**（例如"过了排位，但扣成本就没了"）|
| **不通过** | **0 条**满足，**或**前后半段配对差值**异号**（只在某一段成立）|

**为什么门槛是 95%（而不是 70%）**：

- 一个**完全无优势**的方法，其排位在零分布上是**均匀分布**的
  ⇒ 「排位 ≥ 95%」这件事，**纯运气也有 5% 的概率做到**；
- 门槛取 **95% = 接受 5% 的误判率**（通行尺度；`backtest` 层的判定阈值也是这个量级）；
- 门槛取 **70% ⇒ 30% 的纯随机方法也能"通过"** —— 这条线就**抓不出任何东西**。

**与 `../关于策略/10-测试-机器层验证目标.md` §五 的逐条对应**：

| 该文档 | 本文件 §6.5 |
|---|---|
| 通过 = 显著优于随机，**且前后两段都成立** | 「通过」 |
| 不通过 = 不显著，**或只在某一段成立**（另一段衰减）| 「不通过」 |
| 说不清 = 介于两者之间，只能标"**可能**" | 「说不清」 |

**冻结记录**：报告必须写入 `rule_frozen_at`（本规则写进契约的时刻）。
**改动纪律**：本表的阈值**只许在此处定义一次**；改动它等同于**开一个新实验**，
旧结论依然按旧阈值生效（承 **C4** + `../关于策略/3-认识-思维误区.md`「先写规则，再看结果」）。

### 6.5 留白（本轮不定）

- 报告的**可视化**形式（本阶段不做 UI）
- 多日持有期（当前只到 `t+2`，承 G-3）
- 权重优化 / 组合构建（不在本能力范围）
- 目标 2 所需的「**恒定满仓**」对照（属**时序**对照，另开）
