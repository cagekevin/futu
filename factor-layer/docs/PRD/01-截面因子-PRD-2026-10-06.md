## 一、定位（State 1）

| 维度 | 内容 |
|---|---|
| **做什么** | 把「**某只股票在某一天、在一群同类股票里排第几**」这件事，从原始因子一路做到有效性判决 |
| **给谁用** | ① 你自己（美股选股研究）；② 下游 `backtest/`（消费每日候选池，**可选**）|
| **核心价值** | 补上现有系统缺失的**横截面**那一半 |
| **不做什么** | 不取数、不做时序回测与 PnL、不做组合权重优化、不下单 |

**为什么需要它（不可替代性）**：

现有 `backtest/` 是**纯时序验证**（walk-forward / purge / placebo / 污染未来测试）。它能回答「这个策略有没有偷看未来」，**但回答不了「这个因子有没有排序能力」**。两者失效模式完全不同 —— 缺了后者，前面所有验证都在验证一个可能毫无信息量的信号。

**与已有各层的边界**：

| 层 | 它负责 | factor-layer 的关系 |
|---|---|---|
| `data-layer/` | 原始事实（K线 / 快照 / 复权因子 / 交易日历）| **上游**，只经 `provide` 契约取数 |
| `backtest/` | 单标的 × 时间序列的严格验证 | **并列下游**，互不 import，只经「候选池文件」交接 |
| `frontend/` | 展示（当前为空）| 无直接关系 |

**最高目标（不可违背）**：

> 任何「这个因子能不能选股」的问题，**都能在这里用一套固定流程回答，且结论可复算、可复核。**

**「可回答」验收判据**：

> 给你一个从没见过的因子，能不能**不改任何代码**（只加一个因子文件 + 一行登记）就跑出完整判决？
> 能 ✅ ｜ 不能 ❌（= 流程没抽象对）

### 模块列表（5 个）

| # | 模块 | 职责 |
|---|---|---|
| **M1** | 面板（panel） | 定义截面数据结构的唯一表示（宽表 ⇄ 长表），从 `provide` 取数，按交易日切片票池 |
| **M2** | 暴露（exposure） | 构造 `date × symbol` 的风险暴露矩阵（size = log 市值；industry = 哑变量）|
| **M3** | 因子（factor） | 因子注册表 + 因子实现（每个因子一个文件），产出 `date × symbol` 的**原始**因子值 |
| **M4** | 预处理（preprocess） | 把原始因子变成可横截面比较的标准因子：去极值 → 补缺 → 标准化 → 中性化（**顺序固定**）|
| **M5** | 评估（evaluate） | 判定因子有没有截面选股能力：RankIC / ICIR / 分组单调性 / 换手 + 多重检验判决 |

### 依赖方向（写死，不可逆）

```
M1 面板      →  外部契约（provide，跨进程 JSON）★ 本层**唯一**取数入口
M2 暴露      →  M1（取数经 M1 的 provide_reader —— 承 M1-1）
M3 因子      →  M1
M4 预处理    →  M1、M2、M3
M5 评估      →  M1、M4
```

**跨层依赖（写死）**：

```
data-layer/provide  ──┬──►  factor-layer（横截面：多标的 × 单日）
                      └──►  backtest（时间序列：单标的 × 跨日）

factor-layer  ──►  产物：每日候选池（长表文件）
backtest      ──►  （可选）读候选池文件
```

**factor-layer 与 backtest 互不 import。** 这是本层最重要的架构约束。

## 三、陷阱（State 3）

| # | 陷阱 | 翻车形态 | 为什么危险 |
|---|---|---|---|
| **T1** | **用「今天的票池」回填历史** | `universe.txt` 是当前 328 只，直接跑 2022 年截面 = 用 2026 年才知道的信息选股 | **不会抛错**，只会让 IC 虚高 —— 你以为找到 alpha，其实找到了未来。且 G-2 使其无法完全消除 |
| **T2** | **中性化做错，但 IC 反而更好看** | 忘截距项 / 行业哑变量做完整 one-hot（完全共线）/ 市值不取 log / 缺失暴露的标的静默丢弃 | 这些错法大多让残差更「干净」，**IC 看起来更好**。且都不报错 |
| **T3** | **标签口径与 `backtest/` 不一致** | 图省事写成 `close[t] → close[t+1]`（收盘瞬间无法成交）| 不只是数字不对 —— **两层的结论从此无法互相印证**，而互相印证正是本层存在的理由 |

## 四、约束（State 4）

### 跨模块约束（锚定后续一切细化）

| # | 约束 | 可验证标准 |
|---|---|---|
| **Q1** | **单一取数入口** | 只走 `provide` 契约取数，**禁止 import `data-layer` 的 `store/` `fetch/` `engine/`**。`grep factor-layer/ 的 import → 无 store/fetch/engine` |
| **Q2** | **票池按日切片** | 任何截面计算必须**显式传入**「该日标的集合」，禁止使用全局票池。构造「今日票池跑历史」场景 → 必须报错或显形告警 |
| **Q3** | **标签口径唯一（需求级）** | 口径**在本文件定义**（见 §六），实现允许各层自带；一致性由**跨层契约测试**保证（同一输入 → 两份输出逐位相等）|
| **Q4** | **口径消耗必填** | 预处理 / 评估的全部参数**必填无默认**；`neutralize_method` **禁止 `None`**。不传参数 → 报错 |
| **Q5** | **判决必过多重检验** | 任何「因子有效」的结论必须经 BH 校正，且**报检验次数**。`grep` 判决出口 → 只经 BH，无裸判出口（承 backtest V18）|

### 各模块核心约束

| 模块 | 约束 | 可验证标准 |
|---|---|---|
| **M1 面板** | **M1**：宽表 = 内部唯一表示，长表 = 跨层唯一表示；往返转换**逐位相等** | 往返后 `assert_frame_equal` 通过 |
| | **M2**：**缺就是缺** —— 缺失保持 NaN，禁 ffill / bfill / 填 0 | `grep panel/ → 无 ffill/bfill/fillna`（承 D3/P6）|
| **M2 暴露** | **U1**：`size = log(市值)`；市值缺失 → NaN，**不填 0、不前值填充** | 缺失标的在中性化时**显形剔除并计数** |
| | **U2**：行业哑变量必须**去一列**（或等价处理），禁止完整 one-hot | 构造行业矩阵 → 秩 = 行业数 − 1 |
| **M3 因子** | **A1**：因子**只产原始值** —— 不许在因子内做截尾 / 标准化 / 中性化 | `grep factor/ → 无 winsorize/standardize/neutralize` |
| | **A2**：**注册表制** —— 新增因子 = 加一个文件 + 登记一个名字，框架其余零改动 | 加一个因子 → 只有 1 个新文件 + 1 行登记（承 `strategy_contract.py` 已验证写法）|
| **M4 预处理** | **T1**：**顺序固定** —— 去极值 → 补缺 → 标准化 → 中性化；**调换即报错** | 构造乱序配置 → 报错 |
| | **T2**：每步**改动量显形**（clip 几个 / 填几个 / 剔除几个）| 运行日志必含三组计数（承 P5）|
| | **T3**：**中性化验收** —— 中性化后因子与 `log(市值)` 的截面相关系数 **< 0.02** | 逐日算相关，取绝对值最大者 |
| **M5 评估** | **J1**：**只读** —— 评估不许修改因子值 | `grep evaluate/ → 无对因子值的赋值` |
| | **J2**：**指标最小集六项缺一不可** —— RankIC 序列 / ICIR / IC 胜率 / t 检验 / 分组单调性 / 多空收益 | 报告缺任一项 → 报错 |
| | **J3**：判决**必须报检验次数 + BH 校正结果** | 判决输出含 `n_tests` 与校正后 p 值 |

## 六、地基级固化（定死 vs 留白）

### 6.1 标签口径（**定死**，全仓唯一）

```
forward_return[t] = log(open[t+2] / open[t+1])
末两个位置置 0（边界）
```

**理由**（照 `backtest/target_label.py` 的论证）：`t` 日收盘看到 → 决策 → 实际成交在 `t+1` 开盘 → 收益算到 `t+2` 开盘。用 `close[t] → close[t+1]` 是错的（收盘瞬间无法成交）。

**归属**：定义写在本文件（需求级契约）；`backtest/target_label.py` 保持其既有实现不动；本层自带实现，**一致性由跨层契约测试保证**（Q3）。

### 6.2 预处理顺序（**定死**）

```
原始因子 → ① 去极值 → ② 补缺 → ③ 标准化 → ④ 中性化 → 标准因子
```

**理由**：先去极值（否则均值/标准差被极端值带偏）→ 再补缺（去极值后中位数更稳）→ 再标准化（回归对量纲敏感）→ **最后中性化**（扣掉行业和市值影响后，不该再做任何会重新引入暴露的处理）。

### 6.3 数据结构（**定死**）

|---|---|---|
| **宽表** | `DataFrame`，index = 交易日，columns = 标的 | **内部**：预处理、中性化、IC 计算 |
| **长表** | `(trade_date, symbol, value)` | **对外**：落盘、给 backtest、给 provide |

### 6.4 评估指标最小集（**定死**）

| 指标 | 公式 | 判据 |
|---|---|---|
| RankIC 序列 | 逐日 `Spearman(factor_t, forward_return_t)` | 看**序列**，不是看一个数 |
| ICIR | `mean(RankIC) / std(RankIC)` | > 0.3 可用；> 0.5 好 |
| IC 胜率 | `P(RankIC > 0)` | > 55% 稳定 |
| IC t 检验 | `ttest_1samp(RankIC, 0)` | p < 0.05，**同时报检验次数** |
| 分组单调性 | `Spearman(分位序号, 分位平均收益) × 方向` | > 0.7 单调 |
| 多空收益 | `(top 分位收益 − bottom 分位收益) / 2` | 看方向 + 幅度 |
| **换手** | `Σ\|w_t,i − w_{t−1},i\|`，按买卖方向分别计成本 | 看数值；高换手需扣成本后再判 |

> **修正记录（2026-10-06）**：本表原为**六项**，经用户确认改为**七项**（加「换手」）。
> 理由（按 准确性/复杂度/SSOT）：**准确性** —— IC 显著但月换手 300% 的因子扣成本后可能为负，不报换手判决不完整；**复杂度** —— +0（换手是分箱副产品）；**SSOT** —— 第 1 层 M5 职责描述里已写「换手」，本表漏了，属文档内部不一致。

**分箱规则（定死）**：等频、逐日、`bins = 5`、封顶；多空两边各半仓；**每组样本数必须打印**（防等距分箱导致的组大小不均）。

## 七、跨层接缝（与 data-layer 的契约）

### 7.1 取数方式（**定死**）

照抄 `backtest/data_source.py` 的模式：**跨进程 JSON，走 `provide.cli`，不 import data-layer 内部**。

**理由**（引用 backtest 已踩过的坑）：同进程会让本层的文件名被数据层的**模块命名空间**绑住（它已占用 `config` / `engine` / `store` / `provide` / `fetch` / `data` / `pipeline` / `vendor` / `tests` 等顶层名，且仍在演进）。

### 7.2 ★ 分层原则（2026-10-06 定，来自用户反馈）

> **data-layer 承担全部「数据语义」（什么标的、什么口径）；factor-layer 只做研究逻辑。**

| 谁 | 负责 | 举例 |
|---|---|---|
| **data-layer** | 数据语义 | 哪些代码是股票（排除板块/ETF/非美股）；复权口径；交易日历 |
| **factor-layer** | 研究逻辑 | 因子定义；预处理方法；评估指标；判决规则 |

**由此推导出的三条**：
1. **票池由 data-layer 给**（M1-2）—— 本层不实现任何「标的类型」判定
2. **复权由 data-layer 做**（M3-A3）—— `FactorSpec.adjust` 只是**声明要哪个口径**，不是本层去算复权
3. **接口不可用时必须报错**，不许 fallback 到自己实现（否则原则立刻失效）

## 十、全窗口实跑 + 判决缺口（2026-10-08）

### 10.1 样本量的价值被证实（89 天 → 全窗口 1108 个有效日）

| 因子 | 89 天 | 全窗口 |
|---|---|---|
| `z_neu_ret20` | ICIR +0.124, p=0.315 | ICIR −0.034, p=0.264 |
| `z_neu_ret60` | ICIR +0.028, p=0.886, 天=**27** | ICIR +0.050, p=0.096, 天=**1108** |
| `z_neu_vol20` | ICIR +0.154, p=0.212 | ICIR +0.083, p=**0.0056** |

⇒ 89 天的「不显著」**确实只是样本太短**（`ret60` 从 27 个有效日变成 1108 个）。

### 10.2 ★★ 审计发现 5（判决缺口）：只判「是不是真的」，不判「值不值得做」

PRD §6.4 写「换手必报」的理由是：

> IC 显著但月换手 300% 的因子**扣成本后可能为负**

但 **J2 的约束只写了「必须报换手」，初版实现就只报了、从未用在判决里** ——
`judge_batch` 只消费 `n_days` / `p_value` / `icir` / `monotonicity`，
**`long_short` 与 `turnover` 算了却从未进入判决**。

**实测后果（全窗口，成本假设 5bp）**：

| 因子 | 毛年化 | 成本 | **净年化** | 修正前 | 修正后 |
|---|---|---|---|---|---|
| `z_neu_ret20` | +2.24% | 4.10% | **−1.87%** | not_significant | not_significant |
| `z_neu_ret60` | −1.92% | 2.34% | **−4.27%** | not_significant | not_significant |
| `z_neu_vol20` | +0.75% | 1.80% | **−1.05%** | **significant** ❌ | **not_significant** ✅ |

⇒ **一个净亏损的因子，会被判成「显著」。**

**同类缺口**：`单调性` 对**线性缩放不变** —— `z_neu_ret60` 的单调性是
**−1.000（完美）**，而 5 个分位的平均收益全距只有 **0.00015**（1.5 bp/日）。
只判形状不判幅度 ⇒ 空壳因子照样过。

**修法（承 `写代码4步法` 的退回机制，显式声明）**：

1. `JudgeThresholds` 新增 **3 个必填**：`cost_bps_per_turnover` /
   `min_net_annual_return` / `annualization_days`
   —— **成本是使用者的事实，不是代码的默认值**（承 Q4：口径消耗必填，不猜）
2. `JudgeEntry` 新增 **2 个必填**：`long_short_mean`（归一后）/ `turnover_mean`
3. 判决新增**第 4 条门槛**：`净年化 ≥ min_net_annual_return`
4. 输出新增 5 个可复核字段：`gross_annual_return` / `cost_annual_return` /
   `net_annual_return` / `min_net_annual_return` / `cost_bps_per_turnover`

**测试（+5 条，含隔离性证明）**：

| 用例 | 断言 |
|---|---|
| 显著但净亏 → 必须 not_significant | **先证明前三门确实都过了**（否则是「假通过」）|
| 阳性对照：统计面相同、只有经济面变好 | 必须 significant |
| **隔离性** | 两条用例除经济面外**逐字段相同**，判决必须不同 |
| 三个数可复核 | `毛 − 成本 == 净` |
| 必填无默认 | 缺任一 → `TypeError`；非法值 → 构造时报错 |

> **写这组测试时踩到自己的坑**：初版给的 `icir=0.083` **低于门槛 0.1** ——
> 于是两条用例都是**被 ICIR 挡下的**，经济门槛根本没被触发（「为错误的理由通过」）。
> 修法：把 `icir` 提到门槛之上，并**显式断言前三门都过**。
> **这正是「阳性对照 + 隔离性」存在的意义** —— 它抓的是**测试自己**的漏洞。

### 10.3 全窗口最终结论

```
z_neu_ret20  ICIR −0.034  p=0.264   毛 +2.24%  净 −1.87%  → not_significant
z_neu_ret60  ICIR +0.050  p=0.096   毛 −1.92%  净 −4.27%  → not_significant
z_neu_vol20  ICIR +0.083  p=0.0056  毛 +0.75%  净 −1.05%  → not_significant
票池诊断：270 只、0 只提前结束、no_symbol_ever_left=True
```

**三个经典量价因子，在 1108 个有效日上：统计上有一个显著，经济上全部净亏。**

⚠️ **结论的两条边界**（承 §9.1 ④）：
1. **幸存者偏差高估 IC** ⇒「净亏」的结论**可信**（真实只会更差）
2. **成本假设 5bp 是示例**，不是定论 —— 换低费率券商，`vol20` 的净年化会接近 0
   （**保本成本 2.1bp**），但仍是**薄利**而非 alpha

**测试**：`tests/test_evaluate.py` **53/53**；全层 **151/151**。

### 11.5 三条结论（都来自测量，不来自名字）

**① `max20` ↔ `vol20`：ρ = +0.82 ⇒ 我的先验被推翻**

`max20.py` 的 docstring 原本写着「MAX 是极值统计量不是矩，所以它与 `vol20` 不同」——
**实测 0.82，说明它俩高度冗余**。已把这条实测写回该文件。

> **这是「先验必须显式声明」的价值**：声明了，被推翻时**看得出来**；
> 不声明，就会一直留着一个冗余因子，还以为自己有两个。

**② `turn20` 真正交（|ρ| ≤ 0.10）—— 但那个维度不赚钱**

「量能是唯一没被 `close` 覆盖的维度」**判断正确**（与所有因子 ρ ≈ 0）；
但它的净年化是 **−19.88%**（换手 1.055/日，成本吃掉 19%）。
⇒ **正交 ≠ 有价值**。正交只是必要条件。

**③ `ret5` 是唯一净年化为正的（+2.92%），但 p = 0.077 不显著**

7 个因子的 BH family 里它排第 5（0.0041 / 0.0052 / 0.043 / 0.077 / 0.096 / 0.26 / 0.27），
`0.077 > 5/7 × 0.05 = 0.036` ⇒ **过不了**。

### 11.6 ★ 一个反直觉的观察：ICIR 高 ≠ 多空幅度大

| 因子 | ICIR | 毛年化 | 说明 |
|---|---|---|---|
| `max20` | **+0.086**（最高）| +1.90% | IC 稳定，但**幅度小** |
| `ret5` | +0.053（中等）| **+11.29%** | IC 不够稳，但**幅度大** |

⇒ **ICIR 测的是「IC 的稳定性」，多空幅度取决于「因子在极端分位的区分度」**，
两者**不是一回事**。只看 ICIR 会漏掉 `ret5` 这类"不够稳但幅度大"的因子。

**所以判决的四个门槛（显著性 / ICIR / 单调性 / 净年化）是互补的，缺一不可** ——
这也反过来验证了 §10.2 补第 4 条门槛的必要性。

### 11.7 最终结论

```
7 个因子（含 4 个新族），1110 个有效日，一次 BH → 全部 not_significant
唯一净年化为正的是 ret5（+2.92%），但 p=0.077 过不了 BH
```

⇒ **「换因子类型」在量价范围内没有得到支持。**
量价维度在这 270 只自选股上**已经挖尽**；真要继续，需要**新数据源**（基本面 / 分析师预期 / 财报事件）。
