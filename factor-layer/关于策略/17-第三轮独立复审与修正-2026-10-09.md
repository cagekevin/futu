## 二、第 1/2 条：**"你以为有证据、其实没有"**

复审的话说得很准：

> **同一个错，在新写的、最关键的三个文件上又犯了一次。**

仓库**自己**已经在 `test_causality.py` 的 docstring 里记过这件事：

```
## ⚠️ 为什么必须写成 `unittest.TestCase`（本轮修的缺陷）
原先本文件是「函数 + __main__」风格 —— `python tests/test_causality.py` 能跑，
但门禁口径 `python -m unittest discover -s tests` 扫不到它
⇒ 本仓的 V9 曾经是「名义上的 auto」：测试存在、门禁不执行。
```

**而我新写的 5 个文件（含最关键的 simulator / causality / metrics）又是这个风格。**

⇒ **§10「backtest 97 项全绿」是名义绿**：逐个单独跑确实全过，
但它们**不在闸里**。

### 正确做法（不是补丁）

`unittest` **本来就为这种情况留了扩展点**：包级的 `load_tests` 协议。

⇒ 在 `backtest/tests/__init__.py` 里实现 `load_tests()`：
把每个函数式 `test_*` 包装成 `unittest.FunctionTestCase` **收进门禁**。

这样：
- **门禁口径**（`python -m unittest discover -s tests`）能收到**全部**测试 ✓
- 不用改 5 个文件的写法 ✓
- 以后新加的函数式测试**自动进闸** ✓

## 三、★★ 第 3 条：**仓库有自己的判据，Tugboat 一条都没过**

`backtest/backtest_config.py` 里**预注册**着判据：

```python

MIN_SHARPE = 0.5              # Sharpe < 0.5 → SUSPICIOUS
```

按这套尺子量（复审给的默认配置）：

|---|---|---|
| `MDD_INVALID`（>20%）| −25.84% | **INVALID** |
| `MIN_ANN_RET`（<2%）| 年化 ≈ 1.02% | **INVALID** |
| `MAX_SIDE_RATIO`（>85%）| 单边 100% | **疑似 beta** |
| `MIN_SHARPE`（<0.5）| 0.146 | SUSPICIOUS |

## 四、★ 第 4 条：**随机对照 n=20 没有分辨力，而且两次方向相反**

### 分辨力

```
n=20 次重抽 ⇒ 分位只能取 1/21 的倍数
            最高可达分位 = 95.2%（95% 门槛刚好够不着）
p=0.5 时，分位的标准误 ≈ 11 个百分点
```

### 两次结果**方向相反**

| 出处 | 真实排位 | 我当时的读法 |
|---|---|---|
| `13-验证` 第一次（**有 T8 bug 的候选**）| **70–85 分位** | 「真实**高于**随机」|
| `14-验证` 重做（正确候选）| **30 分位** | 「真实**低于**随机」|

> ### ⛔ **「互相印证」不成立 —— 两次方向是反的。**
>
> 我在 `16` 里写「与 placebo 那次（53.2%）互相印证」，那是**编的**。

而且**两个读法都超出数据能支持的范围**：n=20 下，30 / 50 / 70 分位**互相不可区分**。

**⇒ 正确表述只能是**：

> **「与同规则随机入场不可区分」** ——
> 不能是"跑输随机"，也不能是"高于随机"。

### 更要紧的：**随机对照没有留下任何可复现代码**

`run_tugboat.py` 没有 `--random`，`backtest/tools/` 只有 `audit_conditions.py`。
§3.5 把它列为核心手段、§4.2 报它的数字，**但仓库里没有入口** ——
我是在 `/tmp` 里跑的，**跑完就没了**。

## 六、★ 第 6 条：四阶段"机制级结论"是**交互项假象**

复审把两个作用**拆开**测了：

| 臂 | 笔数 | 总收益 |
|---|---|---|
| 只调 `max_positions`（**不**改出场规则）| 172 | **+2.29%** |
| 只改阶段④出场规则（**不**调仓位数）| 206 | **−4.69%** |
| 两个一起（= 现状）| 171 | **+4.59%** |
| 都不做（= 四阶段关）| 199 | −0.86% |

> **两个组成部分单独都小或负，合起来才 +4.59%。**
> ⇒ **这是交互项主导，不是"四阶段有正贡献"。**

而我在 §4.6 把它列进「**机制级结论（幅度大、方向一致）**」——

> ### ⛔ **恰好搞反了**：交互项主导是**不稳定**的标志，不是稳健的标志。
> 一个由 `A×B` 交互产生的效应，**换个窗口几乎必然翻转**。

## 七、★ 第 10.3 条：`reconcile()` 的**覆盖面被高估**

我一直在说「逐笔对账通过 ⇒ 记账可信」。但复审指出：

> `reconcile()` 验证的是「**我记的和我算的一样**」，
> **不是**「我算的和规则一样」。

**它不覆盖**（而这些都是最可能出错的地方）：

| 不覆盖的 | 为什么危险 |
|---|---|
| 跳空时的 `min(止损, 开盘)` | 按止损价成交会**系统性高估** |
| 同一根 bar 止损优先 | 取错一侧就**系统性高估** |
| 限价 vs 开盘取优 | 取错就高估 |
| `trade_on_close` 当天不判出场 | 我**刚修过**的一个真 bug |

⇒ **`reconcile()` 的绿灯只说明"算术自洽"，不说明"成交逻辑对"。**
