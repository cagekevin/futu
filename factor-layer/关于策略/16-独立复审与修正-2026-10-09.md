## 一、A（最严重）：四阶段曝险有**一天前视**

### 证据链

| 环节 | 代码 | 问题 |
|---|---|---|
| 算状态 | `_market_state()`：`breadth = close > close.rolling(50).mean()`、`dist = spy/rolling(200)−1` | **全按当日 `close`，没有 `shift`** |
| 注入 | `exposure.attach_market_state(...)` | —— |
| **使用** | `trade_simulator` 日循环**步骤 ⓪**（**开盘成交之前**）用它定当日档位 | ⇒ **用今天收盘的宽度，决定今天开盘下多少注** |

### 量化（复现）

| | 前视版 | **因果版（`shift(1)`）** |
|---|---|---|
| 总收益 | −2.65% | **−2.41%** |
| IR（剥离 beta）| −0.182 | **−0.171** |

（复审在**旧版 171 笔**上量到 `+4.59% → +8.50%`，方向一致、幅度更大。）

### 修法

`_market_state` 的返回值**整条 `shift(1)`** —— 开盘前只能看到截至昨天。

### 顺带纠正一处**不对称对比**

文档 §三② 那句「四阶段 开 +4.59% vs 关 −0.86%」是**拿前视版**和
**因果版**（`--no-exposure` 不读市场状态，本来是干净的）**对比**的 ⇒ **两边口径不同**。
现在两边都是因果版。

## 二、B（重要）：**没有任何测试覆盖 Tugboat 的因果性** —— A 就是这么漏过去的

- `backtest/tests/test_causality.py` 的 T1/T2 只遍历
  `strategy_contract.available_strategies()`；
- 而 `strategies/__init__.py` 里**只注册了 `momentum` 与 `regime_gated_momentum`**；
- ⇒ **Tugboat 根本不在里面**；
- 因子层 11 个测试文件里 **0 处**涉及因果/前视；
- `factor_registry._check_values()` 只校验"索引对齐 + warm-up 是 NaN"，**不校验因果**。

⇒ 「无前视」这个结论**只靠人肉读代码 + 条件对账脚本**撑着，
而条件对账脚本**只比对选股条件的布尔值，根本不管市场状态**。

### 修法：新增 `tests/test_tugboat_causality.py`（4 项）

### ★★ 但它的**第一版是错的**（这条比 bug 本身更值得记）

第一版我写的是：

> 「把 `t` **之后**的行情改掉，`t` 当天的状态必须不变」

**结果：去掉 `shift(1)` 之后它照样绿** ⇒ **抓不到那个 bug**。

**根因**：这个 bug **不是"用了未来数据"** ——
`close.rolling(50).mean()` 本来就不会看未来。
真正的错是**时点**：**用"今天收盘"算的状态，去决定"今天开盘"下多少注**。

⇒ **正确判据**：

> **扰动「第 `t` 行本身」，`t` 当天用到的状态必须不变**
> （因为开盘时第 `t` 行还没走完）。

改对之后的判别力（实测）：

```
有 shift   → 4/4 绿
去掉 shift → 「曝险定档不用今天的数据」变红 ✓
```

> ### ★ 写因果测试时的通用教训
>
> 要问的是「**这一天能看到哪些行**」，
> **不是**「有没有用后面的行」——
> 后者会**整类漏掉"时点错"**（而"时点错"正是最隐蔽的一种前视）。

## 三、C（重要）：因子预热吃掉约**一年**窗口

- 库里**最早有 1987-06-16**（共 4,480 天），**完全够预热**；
- 但 `run_tugboat.py` 把面板读成 `days=window`（`>= 2022-05-03`），
  于是 `ret260`（260 天）、`sma200`（200 天）的预热**落在窗口内部**；
- 实测：旧版**第一笔成交在 2023-05-19** —— 距窗口起点 2022-05-03 **约 13 个月**，
  这段**一笔都不会有**；
- ⇒ 可用历史实际 ≈ **3.4 年**，不是文档反复用的 **4.4 年**。

**讽刺的是**：`run_tugboat.py` 自己的 docstring 第 34 行就警告过
"`near_52w_high` 要 250 天预热，选错起点会吃掉大半个窗口"——
**但代码没有任何地方去补预热**。

### 修法

| # | 改了什么 |
|---|---|
| 1 | 面板多吃 `WARMUP_DAYS = 300` 天（评估窗口**不变**）|
| 2 | ★ **新增 `_WindowedPanel`**：面板整体切到窗口 ⇒ **下游所有变体自动一致** |
| 3 | 窗口取"面板**实际有的日子**"的**交集**（`read_days()` 有 `2026-10-08`，面板没有 ⇒ 会 `KeyError`）|

**为什么是包装对象而不是各处 `.loc[window]`**：
靠"每个调用点自己记得切"**必然**有某个变体忘了切 ⇒ 分叉。
（本项目已经因为"分叉"吃过好几次亏。）

### 实测

```
面板   : 1112 天  →  1411 天（含 300 天预热）
首笔成交: 2023-05-19  →  2023-03-06
```

### ★ 检出下限修正

```
旧（错）：4.4 年 ⇒ 1.96/√4.4 ≈ 0.93
新（对）：3.6 年 ⇒ 1.96/√3.6 ≈ 1.04
```

页脚现在**从成交记录算**有效样本（首个信号 → 末尾），不再拿窗口长度充数。

## 四、D（流程）：幸存者偏差告警**没进报告**

- 项目自己的手册（`docs/流程-如何做一次验证`）写着：
  **"幸存者偏差必须显形 —— 报告里带 `universe_diagnostics` 告警"**、**"每次都要带着读"**；

- `15-最终结论` 的"做不到的"与"可信度"表里**也没有**。

⇒ 幸存者偏差的方向是**高估**。这里"负结论可信"恰好靠它，
但**这个关键限定没进头条报告**，读者会以为"这些数字是干净的"。

页脚改成**四个偏差**，并写清一条**很重要**的限定：

> **它不污染「真实 vs 随机」那个对照**（两侧共用同一个池子）
> ⇒ **那个对照是整份工作里最抗偏差的证据。**

## 五、E（次要）：`breadth` 的分母**恒为 270**

```python
breadth = above.sum(axis=1) / above.notna().sum(axis=1).replace(0, np.nan)
```

`above` 是**布尔表** ⇒ `above.notna()` **恒为真** ⇒ 分母恒等于列数。

⇒ 未上市 / 无数据的票被算进"不在 50 日线上方" ⇒ **早期宽度被系统性低估**
（更容易误判成"疑似见底"档，而那一档 `max_positions=1`）。
那句 `.replace(0, np.nan)` 是**死代码**。

**修法**：分母改用 `close.notna() & rolling(50).notna()`。

## 六、F（次要）：**测试规模被低报**

```
unittest discover 只收到 : 39 项  = test_causality(3) + test_statistics(36)
tests/ 下实际            : 8 个文件、115 项
```

原因：本层大多数测试是**函数式**（`def test_xxx() -> bool` + 自己的 runner），
不是 `unittest.TestCase` ⇒ `discover` **一个都收不到**。

⇒ "backtest 97 项全绿"作为**测试规模**没错，但作为
"**核心代码被验证过**"的印象是**失真**的：
真正管 Tugboat 的（simulator / exposure / metrics / causality）**全在 discover 之外**。

### 修法：新增 `tests/run_all.py`

并且它**当场又抓到一个**：

```
❌ test_statistics.py   0 项（退出码 1）
   ImportError: cannot import name 'SINGLE_SERIES_IN_CLUSTER' from 'statistics'
```

**根因**：`backtest/statistics.py` 与**标准库同名**。
直接跑 `test_statistics.py` 时 `sys.path[0]` 是 `tests/` ⇒ `import statistics` 命中**标准库**。
（`discover` 恰好把它放进了 path ⇒ **discover 下能过、直接跑不能过**。）

> **"换种跑法就红"的测试最容易被当成绿。** `run_all.py` 显式设了 `PYTHONPATH`。
