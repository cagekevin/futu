# 架构师新建 4 步法 · **V2**（从零构建 SOP）

> **版本**：本文即 **V2**（原地取代 V1）。
> **共用部分**：与 `架构师改码7步法.md` 共用的判据 / 命令 / 模板，**真源分工见 §0.2**。

**核心心法**：改码是「治病排雷」，新建是「优生防御」。新建没有历史病灶可对照，
必须靠**前置模型设计 + 机器门禁**杜绝把新代码写成明天的技术债。
**全局铁律**：**先想清最优解 → 再定真相 → 再设防腐 → 死磕失败 → 最后画接口。** 敢从接口/消费端往下写，一律打回。

> **本项目（trading-desk）语境**：新建 = 给数据层加**新源 / 新指标 / 新数据项 / 新对外入口**，或给回测层加**新策略 / 新指标**。
> 分层 → `Agent.md` §3；铁律 → `Agent.md` §4；约束 → `data-layer/docs/PRD/`；记录 → `data-layer/docs/plan/`。

| 层 | 强制力 | 手段 | 成本 | 用途 |
| --- | --- | --- | --- | --- |
| **L0 文字** | **无** | 注释 / 文档 / docstring | 极低 | **只解释"为什么"**，不作防线 |
| **L1 契约层** | **运行时报错** | 键校验 · 受控清单 · 单位显式 · 必填字段 | 低 | **优先** |

## 1 · 交付金标准：四零一毁

### 1.1 数据 0 副本（状态绝对收敛）—— **结构偏好（强）**

- **红线**：同一个真相（SSOT）只能有一份；**指标只存"怎么算"（`source_key` + 参数），不冗余存底层值**（承 X1）。
- **边界**：
  - **底层数据** = 会被别处读/被落库/被别人改的（K线 / 期权链 / 快照）⇒ **必须住 `store/`**；
  - **派生量** = 能实时从底层算出的（复权价、对齐面板）⇒ **不落库、按需算**（承"K线存 raw + 因子单独存，下游自算"）。
  - 判据问句：**「这份数据删掉，别处会失忆吗？」** 会 ⇒ 是底层数据，必须进 `store/`。
- **🔍 违反时怎么发现**：
  - `grep -rn "raw\[" data-layer/provide` 之类，看是否在消费端重算/复制底层；
  - 出现"同一指标两处各算一份" ⇒ 铁证。

### 1.2 异常 0 猜测（契约逼迫处理）—— **🔴 红线**

- **红线**：契约自带强迫性，不让调用方猜。**承 P1/P2/P6：缺 / 错 / 不一致 → 停下报清**；禁止 `None`/默认值兜底冒充成功。
- **契约形状**：成功返回真实值；失败**抛明确异常**或返回可判别结果（含可展示原因）。第三方/外部接口的异常必须在**边界**（`fetch/sources/`）转成本系统的明确错误。
- **🔍 违反时怎么发现**：
  - `grep -rn "except.*:\s*pass\|except Exception: *return" data-layer`；
  - `grep -rnE "or None|or \[\]|or \{\}" data-layer`（静默补默认值）；
  - 逐个看失败分支是否带可展示原因。

### 1.3 下游 0 内部知识（无脑消费）—— **结构偏好**

- **红线**：`provide/` 只做"状态投影 + 数据发射"；**下游不需要知道**文件路径 / 格式 / 源名（承 P2）。
- **本仓真实例子**：
  - ❌ **反例**：让下游知道"数据存在某个 json 文件的某层键里" ⇒ 内部存储一改，下游全崩。
  - ✅ **正例**：`provide/api.py::Record` / `_to_row` 给下游干净的行式结构；`backtest/data_source.py` 只经 `provide.cli` 拿 JSON，**不 import 数据层内部**。
- **🔍 违反时怎么发现**：
  - `grep -rn "data-layer\|\.json\|store/" backtest/` ⇒ 下游若出现数据层内部路径即为越界；
  - `provide/` 出现"某用途专用字段" ⇒ 越权（承 P1）。

### 1.4 架构 1 键毁灭（可废弃性）—— **结构偏好，且只适用于业务模块**

- **红线**：新业务可随时安全切除：删掉业务模块 + 改注册表 1~2 行，项目零错跑通。
- **⚠️ 适用范围**：这条**只约束"业务模块"**（新源 / 新指标 / 新回测策略），**不适用于横切地基**
  （`trading_time` / `store/keys` / `config` / `store/storage`…）。地基本就该被依赖，拿"能不能删"量它们 ⇒ 会去拆地基。
- **🔍 违反时怎么发现（可执行）**：删模块 + 改注册 ⇒ 跑 `.venv/bin/python -c "import store, fetch, engine, provide"` 必须 0 错；再 grep 确认没留孤儿引用。

## 2 · 施工 4 步法

### Step 0 · 先写最优解 + 普查拦截（唯一开工前置）

> 🔒 **第一动作不是"查"，是"先写出最优解"**（真源：`架构师改码7步法` Step 0 + A14）。

**0.1 一屏以内写出「正确落地时长什么样」** → **真源 = `架构师改码7步法.md` Step 0**（本文不再复制）。

**0.2 新建三问**（存量改造不会有）：
1. **真的需要"新"吗**？（新建模块是最贵的选项，能加几行就别建 —— 例：能加一个数据项就别建一个新源）
2. **边界在哪**？（哪些**确定**属于它、哪些**确定**不属于；模糊 ⇒ 会长成万能模块）
3. **一键毁灭点在哪**？（需要它不与谁耦合）

**0.3 普查（三查）**：查原语（§5-B 速查表）→ 查相似链路 → **🔥 横向盘查**（同需求在别入口怎么满足的）。
→ **真源 = `架构师改码7步法.md` Step 0 第 3 步**（本文不再复制）。

**0.4 放行判据（红线）** → **真源 = `架构师改码7步法.md` Step 0 开工指令**。
**产出**：表①最优解（一屏）· 表②入口对照表 —— **未出不进 Step 1**。

### Step 1 · 定真相与边界

1. **SSOT**：锁定核心数据的唯一物理位置（`store/` 里 `(交易日, 标的, 数据项)`）。
2. **所有权**：生产者/消费者划分；**消费者严禁执行所有方的动作**，只能经 `provide` 读。
3. **禁幽灵预留（YAGNI）** —— **本文定义段，其余处只引用本节**。
   - 只为当前真实需求写接口；禁为"以后可能"预留抽象/无效参数。
   - 判据：**指不出"现在谁在什么场景用它" ⇒ 删**。
   - 🔍 **怎么发现**：`grep -rn "<新符号>" data-layer backtest` ⇒ **除定义处外 0 命中** 即为幽灵预留；
     `grep -rn "NotImplementedError\|TODO\|以后\|预留" <新模块>` 抓"为未来预留"的痕迹（注意：**明写"未接"的能力缺口 ≠ 预留**，如 `align_daily_items`）。
4. **钉死模型**：结构写死，消灭"随手 `Any`"与无意义 `dict`。
   - **契约权威下沉到"最低变化速率层"**（纯逻辑层，无 IO）。
   - 判据：**具名结构没人 import ⇒ 权威虚设**。
   - 🔍 **怎么发现**：`grep -rn "from <模块> import <类型>" data-layer backtest` 是否 **0 命中**。
5. **🔥 建了原语 ≠ 完成 —— 必须同时规定「谁必须调它」**
   **本节为定义段；Step 4 第 3 条 / 自检只引用本节。**
   每个新增原语写两行：**① 谁必须调它（路径清单，必须穷尽）② 验收方式**。
   - **只列一条 = 假接线**；
   - 验收 = **生产消费 > 0**（`grep` 除定义处外真有命中；**只有测试命中 = 幽灵预留**）。

### Step 2 · 定契约与防腐层

1. **ACL 防腐层**：外部/旧接口/第三方数据**必须在边界洗脱**（`fetch/sources/`），转成 Step 1 的纯净结构后才准进 `store/`。
   - 🔍 **怎么发现**：`grep -rn "Any\b" <新模块>`（绕过结构校验）；`store/`/`engine/` 之外出现原始报文形状 ⇒ 脏结构已进核心。
2. **失败契约**：见 §1.2。
   - 🔍 **怎么发现**：逐个看失败分支是否带可展示原因；`grep -rnE "or None|or \[\]" <新模块>`。
3. **切断默认值兜底**：查不到 ⇒ 抛错或明确的"缺"；**严禁私自塞空值/默认值让逻辑跑通**（承 P1）。
   - 🔍 **怎么发现**：`grep -rnE "\?\? *|or \"\"|or 0|or \[\]" <新模块>`（静默补默认值）。
4. **异常也要洗脱**：第三方/网络接口的**异常在 ACL 转成本系统的明确错误**，不许把裸异常放给核心。
   - 🔍 **怎么发现**：`grep -rn "raise " <新模块>` ⇒ 逐个确认是"不该发生"的编程错误；凡是"预期会失败"的分支都必须转成可判别的失败返回。

### Step 3 · 核心组装与对外投影

1. **纯化运算**：「怎么算」抽成无外部依赖的纯函数（可单测）—— 本项目 `engine/` 就是这一层（**零 IO，承 G1/G2**）。
   - 🔍 **怎么发现**：`engine/` 里出现 `open(` / `requests.` / `urlopen` ⇒ 已被污染。
2. **中心调度黑盒（`store` / `provide`）**：收敛数据与规则，对外**窄接口**；外部"无脑传参"。
   - 🔍 **怎么发现**：`grep -n "^def \|^class " <模块>` 看导出面是否过宽（理想只剩"入口 + 少量结果结构"）。
3. **下游极致降级**：`provide/` 只做投影 + 发射（见 §1.3）；横切出口见 §4.6。
4. **生命周期 / 并发 / 取消**（新业务最容易忽视的一类）：
   - **超时**：联网 / 子进程必须带超时或明确失败路径（禁止无限挂起）。
   - **幂等**：写库的键是 `(交易日, 标的, 数据项)`，**同一天同标同项写两次只应有一个键**（承 K1），禁止自造 `timestamp` 当幂等键。
   - **原子**：写库走 `store/write.py`（原子写，一天一个原子单位，承 L4/X2），禁止直接开文件写。
   - **并发**：本项目为批处理管线，**不要引入并发写库**；确需并发时要么复用既有模式、要么明确论证"不会有并发"，**不许口头假设**。
   - 🔍 **怎么发现**：`grep -n "subprocess\|requests\." <新模块>` ⇒ 每处长任务是否都有超时/失败路径。

### Step 4 · 机器验收与落闸

1. **测试闭环**：核心纯函数 + 边界必须覆盖；**只测黑盒输入/输出**；**失败分支必须断言**。
   **🔒 禁自证式断言**（判据见 `架构师改码7步法.md` §7.2）：判据 —— **把被测实现改坏，断言仍绿 ⇒ 它是装饰，删**。
   验收入口 = **先红后绿**（真源：`架构师改码7步法.md` Step 7.1）。
2. **落闸**：**默认不建**；先过「建约束前置评审」（真源：`架构师心法` §零.4）。能用**结构 / 契约 / 唯一入口 / 对账测试**守住的，**不许用脚本闸**。
3. **接线验收**：对应 Step 1 第 5 条 —— 逐个新原语 `grep` 确认生产消费 > 0；每条写入口逐条核对真的接了。
   - 🔍 **怎么发现**：`grep -rn "<原语>" data-layer backtest` 去掉定义处与 `tests/` 后是否仍有命中（**只有测试命中 = 没接**）。
4. **全局登记**：链路有全局影响 → `Agent.md` §1/§3；新数据项 → `store/keys.py` 的 `KNOWN_ITEMS`（全局项加 `GLOBAL_ITEMS`）；新代码格式 → `data-layer/docs/reference/futu/code-formats.md`；确立/推翻约定 → `Agent.md` §4 或 `data-layer/docs/PRD/`。
5. **裁决闭环**：施工图里标了「待/TODO/TBD」的，交付前**必须给结论**（或明确"不做"）。

## 4 · 模板集（**落点均为本仓实测**）

> ⚠️ **4.1–4.7 只示范结构，不是最优解。**
> **动手前先读 §5-H 的真实范本**（`fetch/fetch_api.py` / `provide/api.py` / `engine/gex.py` 等），**理解了范本之后**再把本模板当骨架用。

### 4.1 目录（物理隔离 + 一键删除）

```
data-layer/
├─ store/      # 库：键 / 存储 / 读 / 写（**零依赖**，承 K5）
├─ fetch/      # 取数：统一出口 + sources/（换源只动这里，承 F3）
├─ engine/     # 计算：纯函数（**零 IO**，承 G1/G2）
├─ provide/    # 对外：api.py / cli.py
├─ pipeline.py # 管线：编排（只调 M2/M3/M1，不实现能力，承 L3）
└─ trading_time.py  # 时间：统一 Unix 秒 + 美东判定
```
**import 约定**：`provide → engine` 是**向下依赖（合法）**；`store` 不许 import `fetch/engine/provide`（K5）；`engine` 不许碰 IO（G1/G2）。
**命名强制项**：**用长名，一看就懂；禁止短名/缩写**。数据源放 `fetch/sources/`（**一个平台一处**）。
> 🔍 **怎么发现**：`grep -rn "^import\|^from" data-layer/store/` 若命中 `fetch|engine|provide` ⇒ 违规（K5）。

### 4.2 types（模型 + 失败契约）

```python
# 结构写死（承 P2），失败用明确异常/可判别结果（承 P1/P6）
from dataclasses import dataclass

@dataclass(frozen=True)
class MyItem:
    day: str
    symbol: str
    item: str
    value: float

# 失败：抛明确异常（承 P6），不返回 None 冒充
class MyError(Exception):
    """数据项计算失败 —— 显形报错。"""
```
❌ 禁止：随手 `Any` · 无意义 `dict` 当业务对象 · `return None` 代替明确失败 · 失败分支无可展示原因。

### 4.3 store（两种读法，按需）
- **单点**：`store/read.py::get`（缺就是缺，抛 `Missing`，承 K4）。
- **序列**：`store/read.py::series`（只含实际存在的日子，不补）。
- **增量起点**：`store/read.py::latest_day`（回答"更新到哪了"，不是"某天有没有"）。
> **判据**：**跟同层的既有实现保持一致**。新读入口默认复用 `Axis`/`read` 的语义，**禁止自造"取最新"降级**。
