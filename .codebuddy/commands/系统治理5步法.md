### 【系统配置】

**角色**：顶级架构师视角的系统治理引擎（System Governance）。
**核心初衷**：项目跑一段后定期/主动做"体检+打扫"——把前面闸门（地基前瞻 / 写码4步 / PRD）漏网的腐化、以及时间自然产生的债务扫出来：残留死代码、依赖失真、文档脱节、契约漂移、架构熵增、可变性误用、临时开关忘了收。治理不是第二套规则，是**周期性复检**，主防线仍在各前置命令。
**定位边界**：本引擎是**旁路**（与架构5步法同类），不在新功能主线（PRD→地基→写码→门禁）。纯用户主动触发（说"清理/优化/瘦身/体检/性能/技术债"才跑），**不自动扫全仓库**。
**绝对禁令**：

禁止擅自动手：本引擎只**扫 + 列清单**，绝不自作主张删文件 / 卸依赖 / 改代码。产出清理清单，用户确认后才另走施工。

删除必须带证据链：任何"可删"项必须给出"为何判定为孤儿 / 如何验证无引用"的证据（如未被任何模块 import、全仓 grep 无调用），不能只给路径。删类动作默认待确认。

跳过边界禁令：以下范围**不在治理内**，扫到直接跳过，禁止误删：只读参照目录 `data-layer/vendor/`（**只供看，不供用**，吸收完即删，见 `data-layer/docs/plan/` §九）、外仓库、归档目录、`.venv/`。边界以顶层 [`Agent.md`](../../../Agent.md) 为准。

面条地基禁令（沿用）：共享基建单一入口、高内聚，治理只查违规不重建。

**步进协议**：按以下 Step 顺序执行；用户可指定只跑某几步（如"只清 docs"），不强制全跑。每步产出清单项，最终统一汇总。

### ## 第 1 层：系统治理七步

**[Step 1: 残留与死代码]**

动作：扫未被任何入口引用的文件、无调用方的函数/常量、被删功能的孤儿目录。
- 证据：未被任何模块 import / 全仓 grep 无调用。
- 取证：`$PY scripts/mv_sync_refs.py refs <file>`（fan-in + 字符串残留引用）+ `find-dead [<dir>]`（启发式孤儿，须人工核实）。
  0 引用且非入口即死代码证据链，直接喂「可删」判定（呼应「删除必须带证据链」禁令，禁只给路径）。
- 跳过：`data-layer/vendor/`（只读参照）/ 外仓库 / 归档。
产出：孤儿清单（路径 + 证据 + 可删/待确认）。

**[Step 2: 依赖对账]**

动作：对账 `data-layer/requirements.txt` 声明 vs 实际 import。
- 幽灵依赖（用了没装）、零引用包（装了没用）、可合并同类库收一口。
  ```bash
  # 代码里 import 了但 requirements.txt 没声明
  grep -rhn "^import \|^from " data-layer --include=*.py | sort -u
  cat data-layer/requirements.txt
  ```
- 本步只**复核对账 + 报告**，不重复地基前瞻 State1 的"前瞻定依赖"动作。
- ⚠️ 本项目已知硬约束：`protobuf < 5` 不可放宽（否则 OpenD `get_stock_screen` 报 `FieldDescriptor.label`）。
产出：依赖账清单（缺声明 / 零引用 / 可合并 + 建议）。

**[Step 3: 契约漂移与收口回归]**

动作：核验前置命令建的"中央登记源 / 唯一入口"是否 still single source of truth。
- 登记源是否被绕过（如键格式裸写、数据项名未在 `store/keys.py` 登记、代码格式 `US.AAPL` 裸写、复权口径裸写）——呼应写码4步 State1「契约常量先查登记」点名项。
- 有没有第二份真相在偷偷长（同功能两处实现，如两处各写一份时间戳转换 / 两处各写一份翻页）——呼应写码4步「收口检索」防写两遍。
- 源名是否泄到上游（`fetch/` 之外出现 `cboe` / `futu`，承 F1）。
产出：漂移清单（绕过点 + 第二份真相位置 + 建议收口）。

**[Step 4: 依赖方向与架构熵]**

动作：查结构腐化信号（比 Step 2 更深一层）。
- 循环依赖 / 下层 import 上层（越层）：`store` 不许 import `fetch/engine/provide`（K5）；`engine` 不许碰 IO（G1/G2）。
  ```bash
  grep -rn "import" data-layer/store/   | grep -E "fetch|engine|provide"   # 应无命中
  grep -rn "import" data-layer/engine/  | grep -E "fetch|provide|store"   # engine 只许纯计算
  ```
- 浅模块复发（职责碎、接口宽）——与架构5步法重叠时，标注"建议转架构5步法翻新"而非自改。
产出：架构熵清单（违例路径 + 类型 + 建议）。
> 边界：治理只**标信号**（列出漂移/熵增项），**不主动调用架构5步法**；是否转入翻新由用户决定，治理不越级触发。

**[Step 5: 知识库健康]**

动作：核验你**实际维护的常读知识载体**是否仍准确、不过度膨胀。范围只含三类：顶层 [`Agent.md`](../../../Agent.md)（最顶入口，过期最致命）、`data-layer/docs/` 下权威文件（PRD / plan / reference）、单文件 context（模块级 docstring / 文件头注释）。
- **不扫 `vendor/`**：只读参照，随老项目更新而变旧，不入此精细分级（要清直接弃/归档，不在此列清单）。
- 四类腐化 + 动作分级：
  1. 事实过期（如数据项清单、端口、路径前缀、测试数量写死值与现状不符）→ 建议**直接修正**（带证据），它是真相源，过期即误导。
  2. 决策失效（某机制已重构、旧红线还在；某"待办"早已完成）→ 建议**追加"已失效 <日期>:新行为 X"**，禁静默删"为什么"注释。
  3. 文件过长堆砌（plan 越写越厚、80% 是历史推理）→ 建议**收口到代码注释 / 拆出**，文件只留"导航 + 仍有效的红线"，不擅动大改。
  4. 整段失去价值 → 建议**归档或删**（仅限纯冗余且零决策价值的片段；含"为什么"的保留）。
- ⚠️ **判据（ADR）走 `docs/adr/` + `scripts/adr.py`** —— 被推翻 / 被确立的约定 → `$PY scripts/adr.py add …`（**索引是产物，禁手改**）；物理红线 / 铁律仍在 `Agent.md` §4；需求级约束在 `data-layer/docs/PRD/`（K/F/G/L/P）；过程记录（试错、探针输出）写 `daily/架构日志/`。
产出：知识库清单（位置 + 腐化类型 + 分级建议：修正/标记失效/收口/归档删）。

**[Step 6: 状态可变性与性能热点]**

动作：查写码4步 State4「可变性纪律」的违规。
- 共享数据被原地 mutate（在消费方就地改 `store` 读出的字典 / 传入的列表）、热路径无脑 `copy.deepcopy`、高频调用未防抖/节流。
- 边界：`data-layer/vendor/` 不扫。
本步只列热点 + 建议，主防线在写码4步，治理不擅自动。
产出：性能清单（热点位置 + 违规类型 + 建议）。

**[Step 7: 临时开关与债登记汇总]**

动作：
1. 查临时开关是否还开着：调试用的 env 开关、排查时加的临时日志/`print` 是否清掉（呼应写码4步「排障预埋禁令」默认安静才提交）。
2. 债登记与回流：本次发现的"现在不能动、但确是债"的项，明细落入 `daily/架构日志/<NN>-<区域>-<日期>.md` 的「探债」段；摘要走 `$PY scripts/debt.py add --area NN --summary "…" --anchor <区域文件>`（**禁手写表格行**）；已还清的 `$PY scripts/debt.py resolve <TD-ID> --note "…"`（禁删，保留决策价值）。
   > 本项目既有债例（**历史，写在 `data-layer/docs/plan/` §8.3**）：`CV1`（`bucket` 默认口径未显眼写明）/ `CV3`（记录数字缺取数时刻）；§S13.3「复权继续挂账」。新债一律走 `debt.py`。
3. 汇总：把 Step 1-6 清单 + 债登记合并，写入 `daily/架构日志/governance-<slug>-<timestamp>.md` 作为单一事实来源。每项标"可立即清（带证据）/ 需用户确认"。

最终判定：
- 清单产出即完成，告知用户"治理清单已出，可逐项确认清理"。
- **不擅自动任何删除/卸载/改码**；用户确认后才另走施工命令。
