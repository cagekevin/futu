# 债务登记 5 步法（低脑力 SOP）

> **一句话总结**：读记录看灯定起点 → 引用检索深挖取证 → 六问+速查表找债（重深度、找母体）→ 明细进实施记录（线索全·解法从简）、摘要进账本 → 收口「1 份必改 + 1 处按需」→ 下一区。
>
> **效率总纲（精力分配）**：本流程的「贵」在**找债深、线索全**；「省」在**解法从简、落盘轻**。
> - 精力 **80% 投在取证与找债**（Step 2/3）：深挖链条、母体、证据——这是质量的唯一来源，不许省。
> - 精力 **20% 投在登记**（Step 4）：只留「可复现线索」，不写「解决方案」。
> - **不写解法**：偿债方向 = 一句话（如「收口到 `store/keys.py` 加键校验」），不展开步骤、不写伪代码、不给论证；业务债的 A/B/C 只给**选项标题**。
> - **线索给全**：每笔债自带「位置 + 证据 + 归属 + 根因 + 爆炸半径」，缺一项 = 没审。
> - **落盘轻**：实施记录只写「探债」表 + 覆盖度表 + 状态行，不写叙述 / 论证 / 沿革。账本一行。

## 零、核心准则与边界

### 1. 基础定位

只管一件事：把一笔债登记下来，并让这块区域越审越清楚、不被反复重审。

- **触发**：用户说「审计 `<区域>` / 排查架构 / 维护记录 / 数据流过期了 / 登记债务」
- **分工（别混）**：
  - `本文件` = 审（发现 + 登记，只读）
  - `架构师改码7步法.md` = 改（施工还债）
  - `系统治理5步法.md` = 旁路复检
- **效力边界**：`Agent.md` §4 物理红线 > `架构师心法.md` > 本步骤
- **精简留痕**：只留可执行步骤

### 2. 审查方向：从最底层出发

```
键 / 契约 / 定义（store/keys.py、类型） → 纯函数（engine/） → store / fetch → provide / pipeline → 下游（backtest / frontend）
```

> 从下游功能 / 消费端往下钻只能看到症状；债的根几乎总在更底层。**底层一条债，抵上层十条。**
> 本仓既有债多集中在**键 / 口径 / 描述层**（如 `CV1` 口径未显眼写明、`CV3` 记录缺取数时刻、复权公式未定）——都是"地基/描述"层的债。

### 3. 三大铁律与禁令

> 🚫 **禁令：只读，不改一行代码**
> 为什么：债往往同源（同一条规则 / 契约生出来的），逐条就地改易改错 / 改重 → 统一交决策架构师一次收口。

> 🚫 **禁令：禁止跑测试**
> 原则：审计 / 登记债时，不准跑任何测试（`tests/test_*.py` 等）。能通过的代码不一定都对，测试不是本流程的验收门槛，债只靠引用检索 / `文件:行号` 取证。碰测试命令即违规。
> 例外（仅限两处）：① 写代码施工还债（走改码7步法）；② 当场修工具债（`.codebuddy/commands/**` / 构建脚本）—— 修完可测作回归。

> **动作限制**：审计时手只准碰「引用检索 / 实施记录 / `Agent.md` §1·§3 / `data-layer/docs/PRD/`」。本流程唯一产出 = 实施记录的「探债」段 + 账本一行。

> 🔒 **铁律：任何"描述"都只是线索，不是结论**
> 债登记、注释、issue、上一轮结论、覆盖表里的"深审"都可能是错的。动手前必须重新取证（引用检索 + 读真实代码）。把描述当"去哪儿看"，不当"是什么"。

> 🔒 **铁律：诚实优先，禁止静默兜底（兜底必留痕）**
> 任何失败 / 降级 / 取不到值 / 走到异常分支的情况，**必须显式留痕**（抛错、打日志/告警、或在账本显式标记），绝不允许静默兜底——即：`except: pass` 吞掉、`return None` 假装成功、`or <默认值>` 无条件兜默认值、`以后再说` 式跳过。
> **为什么**：静默兜底让债「看不见」，是本项目头号伪装型债（承 P1：**禁止默认值兜底**）。看不见 = 没人还 = 越滚越大。
> **兜底也须留痕**：若因客观限制（上游不可用 / 必须降级容错）确要兜底，必须在该处**显式记录**——打日志 + 行内标注 `# 兜底` + 写明原因与责任方，**并据此登记一债**。**任何「无任何痕迹的兜底」= 违约，审计发现即登记一债。**
> **错误必须当场抛，不许转嫁**：失败应在**发生点**抛出，不该靠一个不相干的总线 / 下游 / 外层去"顺便吸收"。凡把错误甩给一个**本不负责此事**的通道去兜底，**审计时即登记为一笔债**：标「转嫁兜底」、归属到真正的责任域（发生点所在模块）、挂 `文件:行号` 证据。
> **一句话内核**：**「一段代码失败了、却没任何人知道，那就是债。」** 判定不看严重程度，只看"失败是否可见"。

> 🔒 **铁律：首判为债、复核翻非债 = 它仍是债（横跳即证据）**
> 找债时，**第一次判断是债、第二次"复核盘"又改成非债**的情况，直接以「债」定论，不许顺手把复杂度合理化掉。
> **为什么**：一个真正"处于正确位置"的复杂逻辑，判断是**稳定**的。能让人反复横跳，恰恰说明**复杂度没放对位置**。
> **动作**：判债后若要"复核推翻"，必须先能说清"复杂度在哪、为何位置正确"；说不清就保留债，账本标 `[首判债·复核疑非债→维持债]`。

## 二、前置准备：覆盖度账与灯图

> "不重复查"的唯一机制。开审前，须在实施记录里按本表登记每个文件的覆盖状态。

### 1. Step 0 · 维护覆盖度表

| 文件层 | 覆盖状态灯 | 轮次/日期 | 证据(引用检索/行号) | 债/裁定 |
| --- | --- | --- | --- | --- |

**5 种合法状态**：未审（会再查）、抽审（欠一轮深审）、深审（只有代码变了才回查）、已裁定非债（禁再当 bug 补）、有债待还。

- **开审规则**：只审 未审 / 抽审 / 回查；深审 不重查（除非代码被改过 → 标 回查）。
- **完备性判定**：表里还有 未审 行，就不许写"该区审完"（已还清 ≠ 覆盖完备）。
- **增量账原则**：只登记本轮新纳入 / 状态变化的行，未变的原样保留、不重抄。

### 2. 数据流覆盖地图（灯的定义）

| 灯 | 含义 | 对应覆盖状态 |
| --- | --- | --- |
| 🟢 | 已审、无债 | 深审（无债）/ 已裁定非债 |
| 🟡 | 已审、有持平 / 待裁定 | 深审 + 持平债 |
| 🔴 | 有债待还 | 有债待还 |
| ⚪ | 未审 / 抽审（欠深审） | 未审 / 抽审 |

**读起点的两步**：先看 `daily/架构日志/index.md` 的区域清单/灯选"该动哪个区" → 再看该区最新区域日志的覆盖度表选"该动哪个文件"。已被改动过的 🟢 文件 → 在覆盖度表里标 回查。

## 三、标准审计 5 步法

### Step 1 · 定起点

**目标**：确定登记哪个区、起手第一个文件，以及本轮不审哪些。

- 读 `daily/架构日志/index.md` 取待审计 / 审计中的区（如无，按「层」自底向上选）。
- 先读 `Agent.md` §1/§3 该区链路。
- 再读 `data-layer/docs/PRD/` 对应模块约束（该区约束的真源 + 覆盖范围）—— 与 `Agent.md` 同级必读，防把别人已收口的判据又抄一份。
- 🔴 **这两步合起来才是"定起点"，禁只做一半**：`Agent.md` 定「这条链上有哪些文件」；PRD 定「这些文件里哪些约束已有真源／覆盖几处」。
- 细粒度进度看该区最新区域日志的覆盖度表（🔴⚪ 优先）。
- 找出该区最底层文件（键定义 / 契约表 / 常量登记表 / 纯函数）。
- 按层从底到顶列出文件清单，对照覆盖度表筛出本轮要审的（不审的写明原因）。
- 查历史旧债：`$PY scripts/debt.py area <NN>` 及 `search "<词>"`。防重审、看是否复发（复发=没治根）。

> **不过关**：找不出"底层文件" → 边界没定清，先定边界再开审。

### Step 2 · 取证

**目标**：确定链路真实面貌，验证 `Agent.md` / PRD 是否过期。

- 对起点文件跑引用检索，看 fan-in（谁 import 它）。
- 读真实代码：找出键 / 契约 / 不变式 / 唯一入口。**优先拿去 `data-layer/docs/PRD/` 对账**（该约束的真源行、覆盖范围是否如表所述）—— 这是「找第二份真源」最快的入口。
- 沿 fan-in 逐级向上核实，标出与 `Agent.md` §1/§3 不符处；PRD 不符处**就地改正**并记入探债。
- 疑似死代码 → 引用检索双证（0 引用且非入口）。

> **不过关**：拿不出引用检索证据 → 自证式审计 = 没审（必须能让别人独立复现）。

### Step 3 · 找债（只读分析，不动手）

**目标**：定性孤例还是母体？是债还是设计？属于哪类？

#### 3.1 归因判定

- **判据**：某个修复能同时消灭 ≥3 个债 → 它是母体（多在契约层/规则层）。
- **三问**：是否某条规则出错？缺机器守卫（红线只在注释）？同一真相被抄多份？
- **产出**：母体 登记一债全消，症状挂其名下；无母体不强行编造，独立登记 N 个债。

#### 3.2 找债速查表（先 grep 扫一遍，再进六问）

> ⚠ **计数≠重要性**：越是 grep 抓不到的（需语义推断 / 跨轮比对），越是母体根因、价值越高。"AI 怎么挖"列是硬动作，必须逐条执行。

| 形态 | 快扫（grep） | AI 怎么挖（硬动作） |
| --- | --- | --- |
| **注释/文档漂移**（最高频） | grep 注释里提到的符号名/文件名/路径，查是否已改名/删改。 | 抽取本文件注释中所有引用的符号/路径 → 逐个验证存在 → 不存在即漂移。 |
| **静默吞/失败伪装成功** | `grep -rn "except.*: *pass\|except Exception: *return\|or None\|or \[\]"`。 | 对每个捕获点读上下文：失败是否被吞、调用方是否知情、是否该上抛/告警。 |
| **死代码/幽灵预留** | 引用检索看 0 引用；`grep -rn "将来\|预留\|暂不\|备用\|后续用\|NotImplementedError"`。 | 双证 0 引用且非入口；对称接口只实现一半的判定为幽灵（**明写"未接"的能力缺口另论**）。 |
| **绕过唯一入口**（高价值·重点项） | 抓裸写法：`grep -rn "open(\|requests\.\|urlopen" data-layer/ \| grep -v "^data-layer/fetch/"`（应只在 `fetch/`）；键里不许有前缀/源名 → 走真源断言 `data-layer/tests/test_fetch.py::test_f1_f3_no_source_name_outside_fetch`（**别手写 `grep futu`**：会命中 `from __future__`，实测 1496 处假阳性）。 | 列全仓"写状态/取数"点，逐点核是否走唯一入口；非入口直写 = 违约。 |
| **SSOT 第二份** | 抓字面量（数据项名、键名、端口等）全库 grep，≥2 处定义 = 第二份。 | 取每个常量/数据项名全仓 grep，出现 ≥2 处定义或同语义不同名 → 第二份。 |
| **口径错位**（高价值） | grep 某判断的所有比较点（时区/单位/复权/大小写）。 | 同一个判断在 N 处出现，逐点对比取值/归一化方式是否一致。 |
| **假护栏/假守卫**（难检·高价值） | grep 守卫骨架：`if ` · `assert` · `validate` · `guard` · `ensure` · `check`。 | **逐条读判据**：是否恒真（常量/env 定值）、空集合判据、依赖从不变化的外界态；再问"这条守卫真挡得住吗"。 |
| **复发/回潮**（难检·高价值） | `$PY scripts/debt.py list --all` 取历史债主题词。 | **跨轮比对**：每个新债先查是否已有同类；同类再现 = 上次没治根（缺闸），记回潮并指向母体。 |

> 🔴 **重点项 · 绕过唯一入口**：架构级母体债。凡查到一处绕过，必顺藤摸瓜列全仓"写状态/取数"点逐一核对。审计中遇到即优先深挖并**挂母体**（本流程只读，不修码）。

##### 3.2.1 难检两项：越难越要挖

**假护栏/假守卫**：真正的假护栏是**语义级**的——守卫判据在现实路径上永远为真、或依赖一个"理论上会变、实际从不改"的开关。必须：① 枚举全仓守卫骨架；② 对每一条追溯判据能否为假；③ 凡"挡不住"却让人以为安全的，记一债。

**复发/回潮**：要求**横向对照历史**。开审先拿到旧债主题词；每发现一个债先查一遍；若同类已存在 = 复发，必须挂回母体并重开根因。

#### 3.3 六层叩问（结合 3.2 扫出的候选进行判定）

1. 同一真相是否被抄成 ≥2 份？（最高频母体）
2. 有没有绕过唯一入口？
3. 错误被静默吞了吗？
4. 有没有死代码 / 死参数 / 假护栏 / 假收窄？
5. 注释与实现一致吗？
6. **实现对了，效果到了吗？（"判据 vs 实况"对账）**

> 判定区分表：若是为一致性而改、处于正确位置的复杂逻辑、缝隙上的唯一实现，则不是债。

##### 第 6 问 · 为什么必须有

前 5 问全部检的是**代码内部的自洽性**。**它们读不出「代码全对、用户却什么都没看到」这一类债。**

> **实证（"入库了看不见"）**：审计「落盘即入库」时，代码层三位一体全部正确，前 5 问一个都过不了关，结论会是「非债」。
> 但用真实数据对账：某静态白名单只覆盖了一部分记录 ⇒ **大部分在 UI 里无处可见**。
> **根因不在任何一处代码，而在"白名单这条静态判据"与"磁盘实况"的差集上。**

**动作**：当被审对象声称"某事已收口 / 已统一 / 已完成"时，**不许只读代码判定**，必须补一次**判据 ↔ 实况对账**：写出该判据在真实数据上应当命中的集合，与实况求差；差集非空即为债。
常见形态：静态清单（白名单 / 枚举 / 映射表）的**隐含假设过期** —— 它写于某个历史时刻，而生产侧的行为已经变了，清单却没跟着扩。

> **便宜的做法**：直接查真实库 / 真实目录，用命令与该判据的条件对比。**读代码永远读不出"大部分记录无处可见"。**
> ⚠️ 本节只读（查库 / 查目录，不改码、不跑测试）。

#### 3.4 标定归属与证据闸

- 分类为 **结构债**（删重复/补守卫等） 或 **业务债**（改功能/改对外契约等 → 必须标 待用户拍板 并摆 A/B/C 选项）。两者均不在本流程施工。
- **真假红线判定**：拿不出 `Agent.md` §4 级证据即为假习惯，债成立。
- **证据闸**：每笔债、每个非债结论必须挂引用检索或 `文件:行号`。

> **不过关**：判"不是债"也必须留痕（账本标 `[已裁定 非债]`），防被 AI 反复重审。

### Step 4 · 登记

#### 4.1 明细入实施记录（「探债」段）

**格式（线索全 · 解法从简）**：

```
| ID | 位置(文件:行号 / 引用检索) | 债的形态 | 归属(模块) | 爆炸半径 | 利息 | 根因(母体?/孤例) | 大致解法(一句话·可选) | 状态 |
```

> 列的含义都是「线索」，不是「方案」：位置+证据让任何人能独立复现；归属+根因+爆炸半径让还债人能估代价；大致解法只是方向提示，不展开。

**一票打回（只卡线索完整性，不卡解法）**：① 挂不出证据；② 业务债未给 A/B/C **选项标题**；③ 线索缺项。

**ID 规则**：跨区只写 `@见 <ID>`；已还清状态改 `已解决`（禁删）。

#### 4.2 摘要入账（跑命令，禁手写）

```bash
PY=data-layer/.venv/bin/python
$PY scripts/debt.py add --area 02 --summary "…" --class 增债 --rate 中 --anchor <区域文件>
$PY scripts/debt.py resolve TD-02-23 --note "…"
```

> **字段白名单强校验（写入口硬拒）**：归类（还债/持平/增债）· 利息（**只有 高/中/低 三档**）· 归属（结构债/业务债）。摘要 **≤120 字**且**禁裸竖线 `|`**（用「／」）。锚点**只准区域日志文件名**（`<NN>-<区域>-<日期>.md`，须存在）。
> **写前先裁**：把摘要按 120 字裁好再敲命令 —— 返工成本高于裁剪成本。

#### 4.3 更新覆盖度表

按 Step 0 更新状态，必须包含本轮判非债的文件。

### Step 5 · 收口（1 份必改 + 1 处按需）

| 动作 | 源文件/操作规则 | 要求 |
| --- | --- | --- |
| **必改** | 本轮实施记录 | 只写「探债」表（线索全·解法从简）+ 覆盖度表 + 状态行；**不写**快照/溯源/结论等叙述段。报覆盖账：本轮审 M / 共 N / 未审 K（逐个列名+理由）。 |
| **按需** | `Agent.md` §1/§3 | 仅链路漂移时改现状；没漂移就在实施记录写「已对账一致」。禁追加更新叙事段。 |
| **写账** | `scripts/debt.py` | 跑 `add` / `resolve` / `archive`（**写入口，必须跑**）。 |
| **收尾** | 进入下一区 | 选取下一个 待审计。 |

> **不过关**：实施记录没写状态行 / 没报覆盖账 = 没闭环，禁止开下一区。

# 异常与容错代码禁止项（原则：禁止静默吞异常、隐藏失败状态；失败与正常必须在结果上区分；所有异常必须可观测）

1. **异步 / 联网 / 子进程**
❌ 禁止空 catch：`except: pass`；捕获错误必须写日志或上报（唯一例外：经回读校验的"预期内失败"，须显式标 `# 兜底: <理由>` 并留痕）。
❌ 禁止不校验返回码就用结果（本项目：看 `returncode` / 返回码 / 内容日期）。
❌ 禁止不处理子进程/异步异常，产生"未观察到的失败"。
❌ 禁止在清理/`finally` 块里抛出未捕获异常。

2. **同步容错工具（解析 / 转换）**
❌ 禁止捕获异常后直接 `return None` / 默认值 / 空串，不记录错误。
❌ 禁止返回"值或空"的单一类型；必须**成败可判别**（明确异常 / 判别结果），禁止用 `None` 冒充。
❌ 禁止仅靠强制类型转换而不做结构校验（承 P2）。
❌ 禁止调用容错工具后不判成败，直接读值。

3. **副作用与生命周期**
❌ 长任务/联网必须带超时或明确失败路径。
❌ 禁止在清理阶段抛裸异常。
❌ 危险计算禁止不捕获异常直接上抛，掩盖真实原因。

4. **类型与空值兜底**
❌ 禁止把 `Any` 当具体类型直接取字段（承 P2）。
❌ 禁止用 `or` / 默认值强行填充掩盖缺失字段（**承 P1：缺 → 报错**）。

5. **定时器、回调**
❌ 定时/回调内异常必须捕获并留痕。
❌ 回调禁止空 catch 吞掉异常。

6. **接口与错误边界**
❌ 返回成功但业务错误码时，禁止跳过错误判断直接使用数据。
❌ 顶层兜底不能静默隐藏；捕获到错误必须上报/留痕。

7. **异步补充**
❌ 禁止 catch 后人为制造假成功对象。
❌ 禁止丢弃异常不做捕获。
❌ 禁止用异常处理"可预期业务失败"；业务失败必须用可判别结果返回，异常仅用于程序不可预期错误。

8. **对象、解构、参数默认值兜底**
❌ 禁止就地使用可变默认值（`def f(x=[])`），掩盖缺失同时制造共享引用 bug。
❌ 禁止用字典展开静默补全缺失字段，无日志无校验。

9. **状态与副作用**
❌ 禁止 catch 后写入残缺/占位模拟数据，掩盖真实失败。
❌ 禁止在计算阶段执行可变副作用。

10. **序列化、重试**
❌ 禁止重试工具无条件重试全部错误（**禁把程序 bug 当网络异常重试**）。
❌ 禁止重试逻辑丢失原始 error cause，只保留自定义 message。

11. **try-except 块范围约束**
❌ 禁止超大 try 块包裹多段无关逻辑，所有不同根因异常全部归一返回空。
❌ 禁止 catch 后不中断主流程，继续用已损坏的上下文执行。

12. **SSOT 职责边界**
❌ 禁止消费方复制真相源的业务判据，不调用导出的源函数，制造第二份判据。
❌ 禁止在消费端直接 mutate 生产者数据。
❌ 禁止同一套业务规则，静态声明与运行时判断两套不一致逻辑。

13. **标记、测试相关**
❌ 禁止滥用 `# 兜底:` 注释标记（无任何自动校验）；写标记前必须回读校验被捕获代码；同一语义出现 >=3 次，必须收口为原语。
❌ 禁止为了单测能跑通，在业务代码新增专门适配测试的兜底分支（兜底净减原则）。
❌ **禁止自证式断言** —— 判据：**把被测实现改坏，断言仍绿 ⇒ 它是装饰，删**。

**审计规则**：任意一条命中 → BUG，写明原因；全部满足 → PASSED。
