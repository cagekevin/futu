# UI 细节 8 查（界面验收 SOP · 一票否决）

> **定位**：任何"看得见的东西"（页面 / 面板 / 弹窗 / mockup / 组件改样式）在说"做完了"之前，**必须过这 8 查**。
> **一票否决**：**任何一查没过 ⇒ 整份不许打勾**，不许"部分通过"、不许"这条以后再改"、不许用"看起来没问题"当凭证。
> **效力边界**：用户裁定 > 本文件 > 个人审美。用户明确否过的东西直接进红线，不必再讨论。
>
> **⚠️ 本项目现状**：`frontend/` **尚未建立**（`trading-desk/` = 数据层 + 回测层 + 前端三层并列，前端为空）。
> 本文的**判据（8 查）**是通用的、现在就可用于任何 mockup；但**具体令牌 / 组件真源**必须在 `frontend/` 建立后
> **在此登记**（见「查 4」「查 6」「查 0」中的 `【待建】` 处）—— 未登记前不得凭印象引用某个色值 / 组件路径。
>
> **取证纪律（本机血泪）**：
> ① 一律用 **Grep 工具（ripgrep）**，**不许用 shell `grep`** —— 本机 BSD grep 下 `--include=*.ts` 会被 zsh 当 glob 报错、`\|` 交替会**静默返回空**，空结果 = 最危险的假证据。
> ② 每查都要**能复算**：写完把命令 + 输出贴进轮次文件，别写"已检查"。
> ③ 目标是**会动的文件**（并行会话常见）⇒ **下结论前核一遍 mtime**，结论一律标"截至 HH:MM"。

## 用法（三步）

1. **逐查跑一遍**，每查填 `✅ 通过 / ❌ 未过 + 证据行号`。
2. **❌ 就改**，改完**重跑那一查**（不是只改那一处就算过）。
3. 8 查全绿 ⇒ 才允许在下方「验收栏」打勾并附命令输出。

---

## 查 1 · 间距：**来源唯一**

**判据**：同一段间距**只许有一个来源**。外层给了 padding，子项就不许再写同方向的值；不许用**负 margin** 打补丁。

**取证**

- 数一遍水平留白写了几处：`Grep "padding:.*32px|margin:.*32px"` → **只许 1 处**（外层容器）。
- 找补丁：`Grep "margin:-"` → **0 命中**。
- 找重复：同一容器里 `.grid{margin-bottom}` + 下一块 `.header{padding-top}` **同时存在** = 同一段间距算了两遍。

**修法**：外层 `body{padding:0 32px}` 一处；区块间距交给**一个**选择器（首项用 `:first-child` 归零）。

---

## 查 2 · 线条：**每条线都要说得出职责**

**判据**：页面上每一条线（border / 分隔线 / divider）都必须能回答"**它分隔了哪两种东西**"。答不出 ⇒ **删**。

**取证**：`Grep "border-top|border-bottom|border:1px dashed|1px solid var\(--"` → 逐条过。

**该留的**（有职责）：容器边框、拖拽区虚线（它靠虚线表达"放这儿"）、弹窗底部按钮条（分隔"读内容 / 做动作"——但**仅限确认框**，表单弹窗不需要，见查 8 反例）。

**该删的**：卡片本身已有边框、红字 + 图标已说明"这张有问题"，再画一条是在重复表达同一件事。

---

## 查 3 · 对齐：**同一排必须等高，同款必须同规格**

**判据**

1. 同一排的控件**高度必须相等**（差 1px 就能看出来）。
2. 同类元素（chip / 按钮 / 输入框）**全页只有一套规格**，不许两处各写一份。
3. **图标 + 中文**的按钮：必须 `line-height:1`（中文在 flex 里默认 `normal` 会多出 2~3px 行距，字看着往下掉），图标加 `flex:none`。

**取证**

- 量高度：`Grep "height:3[0-9]px|height:2[0-9]px"` 看同一排的取值。
- 找同款不同规格：`Grep "border-radius:10px" 与 "border-radius:8px"` —— chip 出现两种 padding/字号即为违规。

---

## 查 4 · 令牌：**不许有裸色**

**判据**：颜色一律走**本项目的设计令牌**（`【待建】`：`frontend/` 建立后在此登记令牌前缀与文件）；**mockup 必须引用令牌文件，不抄色值**。

**取证**

- `Grep "#[0-9a-fA-F]{6}"` → 命中逐个交代来源。允许的例外必须**逐个登记**（`【待建】`：登记已知例外色值）。
- `Grep "rgba\([0-9]"` → 必须 0 命中（要写成通道变量形式）。
- 常用对照（`【待建】`）：`frontend/` 建立后把"背景 / 面板 / 卡片 / hover / 输入框 / 边框 / 文字各级 / danger"的令牌名与值登记在此。
- 字号**只有登记在册的那几档**：出现不在档的字号即为违规。

---

## 查 5 · 不换行：**按钮与标签一律单行**

**判据**：按钮、菜单项、chip、下拉、提示条 → **`white-space:nowrap`**；菜单宽度不许写死（用 `width:max-content` + `min-width` + `max-width`）。

**取证**：`Grep "white-space"` 覆盖是否齐全；`Grep "width:1[0-9][0-9]px"` 看菜单是否被写死宽度。

**反例**：菜单写死 `width:150px` ⇒ 长文案折成两行。

---

## 查 6 · 组件：**照抄现有的，不许自造**

**判据**：已有组件就照它的形态，不另造一份近似的。

| 控件 | 真源 | 形态 |
| --- | --- | --- |
| 开关 | `【待建】`（`frontend/` 建立后登记路径） | `【待建】` |
| 主按钮 | `【待建】` | `【待建】` |
| 弹窗 | `【待建】` | `【待建】` |
| 输入框 | `【待建】` | `【待建】` |

> **建立 `frontend/` 后**：把每个通用件的**唯一真源路径 + 形态**登记进上表；此后一律照抄真源，禁自造。

---

## 查 7 · 状态与文案：**正常零状态，异常才说话**

**判据**

1. **正常态不显示** 徽章 / 状态 / 版本 / 计数 / 时间。
2. **异常才多说一句**，且**必须带一个动作**（不许只描述不给出口）。
3. **读不到 ≠ 没有**：读盘/取数失败**不许**渲染成空态，必须保留已读到的内容 + 重试。（**承 `Agent.md` §4：失败必须诚实可见**——这条与本项目数据层铁律同源。）
4. 文案里**不许出现实现黑话**（磁盘 / 目录 / 索引 / 注入 / 预算 / 兜底）。
5. **动作语义单一**：同一个动作不许有两个入口。

**取证**：`Grep "title=|aria-label="` 图标按钮是否都有无障碍文案；空/失败态分支是否共用同一个组件。

---

## 查 8 · 可点性：**热区、入口、层级**

> ⚠️ **判据适用面（别把个案升格成通则）**：本条否的是**某个具体位置**。
> **不是**"hover 机制不许用"。写判据前先问：**我改的是实例，还是规则？** 实例错 ⇒ 改实例；只有规则本身错，才立通则。

### 8.1 hover 才出现的控件 —— **允许**，但必须三条全满足

| # | 约束 | 怎么验 |
| --- | --- | --- |
| a | **与同排控件同一基线**：不许孤零零挂在不相干的角落 | 看它出现时，能否与同排某个常显控件连成一条线 |
| b | **出现时不改变布局**：不许挤开、位移、撑高任何元素 | 用 `position:absolute` 或预留槽位，hover 前后量一遍邻居的位置 |
| c | **不是唯一入口**：它承载的动作必须另有常驻可达路径 | 遮住这个 hover 控件，动作还能不能完成？不能 ⇒ 违规 |

**不满足任一 ⇒ 改**：要么挪到对齐的位置、要么常显、要么收进点开的面板/菜单。

### 8.2 其余三条（通用）

1. **右键不能是唯一入口**（触屏 / 键盘没有右键，发现性 = 0）⇒ 必须有可见入口承载同一组动作。
2. 行/卡上的开关**独立热区** + `stopPropagation`，点开关不许连带进详情。
3. **不钻层**：分区用**折叠**（同页收起一段），不用"进入 / 返回上级"。折叠 ≠ 换页。

## 查 0（前置）· **先找通用件，别手写**

动手前先问："这个东西仓库里是不是已经有了？" 手写一份 = 第二份真源（本仓红线）。

| 需要 | 用这个 | 出处 |
| --- | --- | --- |
| 通用件 | `【待建】`（`frontend/` 建立后在此登记：开关 / 弹窗 / 下拉 / 就地命名 / 主按钮 / 拖入高亮 …） | `【待建】` |

> **本项目现状**：`frontend/` 为空 ⇒ 暂无既有通用件。建立前端时，**第一件事**就是把通用件收口成唯一真源并登记进本表。

## 验收栏（8 查全绿才能打勾）

```
[ ] 查1 间距来源唯一     证据：Grep "padding:.*32px" → 1 处；Grep "margin:-" → 0
[ ] 查2 线条各有职责     证据：逐条 border 说明（写不出 = 已删）
[ ] 查3 对齐与规格唯一   证据：同排高度 [ ]；chip 规格 [ ]
[ ] 查4 令牌无裸色       证据：Grep "#[0-9a-f]{6}" → 仅 [ ] 个已登记例外
[ ] 查5 按钮不换行       证据：nowrap 覆盖 [ ] 处；菜单 width:max-content
[ ] 查6 组件照抄         证据：开关 [ ] / 主按钮 [ ] / 弹窗 [ ] 对齐真源
[ ] 查7 状态与文案       证据：正常态零状态 [ ]；异常带动作 [ ]；读失败≠空态 [ ]
[ ] 查8 可点性           证据：hover 控件 [ ] 个，逐个验 a基线/b不改布局/c非唯一入口；右键非唯一入口 [ ]
```

**打勾条件**：8 个框全勾 **且** 每条后面贴了命令 + 输出。**任一未过 ⇒ 不许打勾，也不许说"基本完成"。**

## 三条不许

1. **不许分批打勾**：这不是"完成度进度条"，是闸门。
2. **不许用截图代替取证**：截图表象，判据要可复算（行号 / 命令输出）。
3. **不许把"某个位置不好"写成"这个机制不许用"**。
   ⇒ 立判据前先自检：**用户否的是实例还是规则？** 否实例 ⇒ 判据写成"约束条件"，不写"禁止"。
