## 🎯 中心思想（其余全是它的展开）

> ### **同一件事只许一条判据。**
>
> 多出来的只有三种去处：
>
> | 多出来的那条是                 | 处置                         |
> | ----------------------- | -------------------------- |
> | **同族的两面**（换个入口问，答案同一张表） | **合并**，且合并后必须是**一条线**      |
> | **判据重复**（各域语义差异是域内必需的）  | **禁合并**，只**钉边界**           |
> | **没必要的**                | **别写** —— 判据是稀缺资源，不是决策日志 |
>
> ⇒ 一切动作只为一个目标：**让"同一件事"在仓里只有一个答案，而且这个答案能被发现违反。**
> ⇒ 且这条答案**必须能指导下一个 AI 的动作** —— **不能的，判过期或改写成让架构更好的**（见铁律 1）。
> ⇒ 且这条答案**要写在 AI 一定会读的那一行** —— 它读的是 `Agent.md` §4 的铁律行 / PRD 的约束行，**不是正文**（见下「补丁打在病灶」）。

## 一条判据该长什么样（**判据 + SOP，不写推理**）

| 要 | 不要（写了就是"推理过程"，抽走） |
| --- | --- |
| **判据**：一句话能照做的规则（"键里无源名 / 无前缀"） | 试错过程 · 探针输出 · A/B/C 比选 · "我以为/后来发现/当时" |
| **SOP**：发现违反后怎么做（命令 + 期望输出 + 处置） | "所以要小心…""希望后续…" |
| **边界表**：与谁互补 / 与谁不重叠 | 大段背景叙述 |
| **落点**：`文件:行` / 唯一入口 | 只有文档编号（= 未实现） |

**格式**：结论 ≤120 字 · 正文 ≤80 行 · 六节齐（背景 / 判据 / 决议 / 后果 / Lessons Learned / 落点）· **过程一律归 `data-layer/docs/plan/`**。
**推理过程不是废话** —— 它只是**落错了地方**：归实施记录留痕（弯路最贵），判据只留**裁定后的规则**。

**⚡ 补丁打在病灶 = 读者一定会读到的那一行**：
**铁律行 / 约束行是判据的门面**（AI 读判据的入口）⇒ 收窄 / 加前提 / 判例外 / 标过期之后，**必须回读那一行并问：「只读这一行的人，会不会做错？」**
⇒ 修一条判据 = **正文 + 门面行**两处一起改；**只改正文 = 没打上**。

## ⚠️ 铁律（违反重做）

| #     | 铁律             | 判据（一句话）                                                                                        |
| ----- | -------------- | ---------------------------------------------------------------------------------------------- |
| **1** | **宁缺毋滥**       | **一次最多新建 3 条**；到第 3 条先答「这 3 条属于同一类吗」（同类 ⇒ 那是 1 条）。能改现有条就别开新条；**写下它之后没有哪个具体动作会改变 ⇒ 不写**。**没有指导意义的不占位置** —— 下一个 AI 读完答不出"我该做什么 / 不该做什么"⇒ **判过期**或**改写成让架构更好的判据** |
| **2** | **相近先分后动**     | 同族两面 ⇒ 合并；判据重复 ⇒ **禁合并、只钉边界**。**合并 ≠ 拼接**：自检题「删掉中间任一段，其余还独立成立吗？」—— 成立 ⇒ 你写的是两条，不是一条            |
| **3** | **判据不许反向拉低架构** | 不许「保留在用的那份、删掉新地基」· 不许「再抄一份」· 不许「写不出检查就删掉规则」· **判据与现状必须一致**（过期 ⇒ 幽灵违规 ⇒ 假债） |
| **4** | **决策前置过门槛** | **只在两个观察点过三关 + 留痕**（① 拍板前；② 落账时）。三关内容 / 留痕格式见 `架构师心法` §零.4 与 `架构师改码7步法` Step 5。「以往约定」**不是一档，是资格筛**（答不出「凭什么成立」即出局）；拿它当依据 = 违铁律 6。 |

## 怎么做

### Step 1 · 体检 —— 找打架的、找会让架构变差的

> **一键编排**：`data-layer/.venv/bin/python scripts/adr.py doctor`（= audit + hygiene + refs --check；只读 · **不是闸**）。
> ⚠️ `doctor` 第 ④ 步（前人弯路 `extract-detours`）**未搬** —— 脚本会**显式跳过**（不假装跑过）。

```bash
PY=data-layer/.venv/bin/python
$PY scripts/adr.py list              # 现行判据（--all 含已退出）
$PY scripts/adr.py audit             # 形式一致性（只读 · 不是闸）
$PY scripts/adr.py hygiene           # 可数体检：空壳 / 近义簇 / 未毕业 / 今日新增
$PY scripts/adr.py refs --check      # 跨条断链（引用了已不存在的编号）
$PY scripts/adr.py stats             # 状态分布
```

**顺序是硬的：先判据，再弯路。** 判据说"现在是什么规矩"，实施记录说"**这条规矩以前出过什么事**"。缺后者，你会把**已经翻过车的处方**当新发现重新推一遍。

- **过期与否由证据判，不靠感觉**：判据引用的目录/文件/行号若已不存在，就是在报**幽灵违规**。拿命令核（如 `ls data-layer/store/keys.py`）。
- **读法 = 定向检索，不是通读**：拿本次要审的判据编号 / 主题去搜实施记录（如 `口径` · `复权` · `源名` · `假债` · `误诊`），找**同类形态**。

**闸绿 ≠ 健康** —— 形式检查只查"有没有三件"，**不查横向一致性**（同一现状两条判得一样吗）。一上手就全绿，正是要继续查的信号。

**十问**（逐条读全文；每条发现给 `文件:行`）：

| # | 问                       | 命中长什么样                                            |
| - | ----------------------- | ------------------------------------------------- |
| **⓿** | **门面行 vs 它自己的正文，同步了吗？**（**必查第一问**） | 正文已收窄 / 加前提 / 判例外 / 标过期，**门面行仍是旧话** ⇒ AI 只读门面就动手 |
| ① | 同一现状，两条判得一样吗？           | 把各条「违反判据」**真跑一遍**，找"A 报违规 / B 报合规"                |
| ② | 判据里写死的目录 / 文件 / 行号过期了吗？ | 判据列的路径/符号已不存在 ⇒ 一直在报**幽灵违规**                |
| ③ | 有没有「绝对句」与「自认边界」对撞？      | 「写不出检查 ⇒ 规则不成立」 vs 「本项没有机器防线，硬凑的 grep 更坏」         |
| ④ | 后立者收窄了先立者，**先立者有指针吗**？  | 单向补丁 ⇒ 只读先立者的人照旧产假债                           |
| ⑤ | 两条都自称「唯一路径」但指不同手段？      | 读者被迫猜 = "两条路看起来都对"                                |
| ⑥ | 引用了**不存在的编号**吗？         | 删号 / 合并必然漏扫引用面 ⇒ 论据指向空气                           |
| ⑦ | 「违反判据」还**红得起来**吗？       | 它引用的字段已被别的判据移出 ⇒ 那条违规**写不出来** ⇒ 判据成了装饰 |
| ⑧ | 正文混进**推理过程**了吗？         | 试错 / 探针输出 / A/B/C 比选 / "我以为·后来发现" ⇒ **抽成判据 + SOP**，过程归实施记录 |
| ⑨ | 对下一个 AI **有指导意义**吗？      | 读完答不出"我该做什么 / 不该做什么"⇒ **判过期**或**改写成让架构更好的判据** |

**每条判据必须服务于架构的正确性，而非掩盖问题 —— 三条合格判据（缺一即不合格）：**

| # | 判据                  | 不合格信号                                       |
| - | ------------------- | ------------------------------------------ |
| ① | **复杂度实减**：链路**更短、更直** | 用适配器 / 兜底把复杂度**藏进黑盒**（搬家 ≠ 消灭）             |
| ② | **失败诚实**：错误在**根部炸开** | 决议鼓励了静默 catch / 默认值兜底 / 假装成功                |
| ③ | **SSOT 收口**：同一能力的判断逻辑收口为 **1 份** | 仍是 N 份判据，或新增了第二份真相                         |

⇒ 三条全过才配留在现行集；不过的按下表六形态定位病灶（**③④⑤⑥ 改判据本身** · **② 打回重写** · ① 见铁律 3）。

> ⚠️ **「为拆而拆」禁令**
> 有 AI 以「判据要求建 / 拆封装」为由要**拆封装**，被拦下 —— **拆完调用方各自直插内部件，入口 1 → N、链路更长**，反而更差。
> **守护者不判"这个封装该不该拆"（那是架构师的活，越界），判的是：能不能拿这条判据当依据去拆。**
>
> **反拆四问（⓿ 不过 ⇒ 禁做；①②③ 任一不降 ⇒ 不许做）**：
>
> | 问 | 判据（可数，不许凭感觉） |
> | --- | --- |
> | **⓿ 正确性**（最先问） | **用户能做的事变少了吗**？变少 ⇒ **禁做**，摆 A/B/C 交用户 —— 它是**必要条件**，不是加分项 |
> | ① **复杂度** | **链路环节数**改前 vs 改后 —— 更短才合格（搬家 ≠ 消灭） |
> | ② **SSOT** | 同一能力的**入口数**是 1 还是 N？**1 → N = 破坏** |
> | ③ **交扯指数** | **跨目录未走入口直插的次数**下降了吗？ |
>
> ⇒ **拿不出 ⇒ 不许拆**。
> **根因**：封装是"窄接口"的一种实现，**判据是接口宽度**，**不是"有没有封装"**。
> ⇒ 拿"判据说要有 / 不要有封装"当依据 = **违反铁律 6（既有约定不是判据来源）** —— 先答「它凭什么成立」，答不出就不许动。

**会让架构变差的六种形态**：

① 用"可测量"冒充"正确" · ② 无条件奖励旧实现 · ③ 判据本体与边界分家 ·
④ 缺"什么算"的判据（主观量词） · ⑤ 常红判据 · ⑥ 禁用一切防线却没写"存量痕迹怎么办"。

⇒ **③④⑤⑥ 改判据本身**（不是加提醒）· **② 打回重写** · ① 见铁律 3。

### Step 2 · 收编 —— 合并 / 钉边界 / 退役

> 走 `adr.py`：`add`（新条）/ `status <NNNN> --to 已取代 --by <新号>` / `index --write` / `audit`（必须 0 问题）。

**合并后必须是一条线**：
`旧约定 → 当初为什么这么定 → 凭什么不成立（取证）→ 新判据 → 与谁互补（边界表）→ 怎么发现"又回去了" → 落点`
外加 `## Lessons Learned`。边界表范本 = **两列对照 + 一句总判据**。

**第 3 步 · 回改三处（漏一处 = 没做）**：
① 全仓改旧编号引用（活跃文档必改，`data-layer/docs/plan/` 历史记录不改）·
② **被收窄的那条加头部指针** · ③ 新条头部写清 `取代`。

> **单向补丁是本仓的高发病**：给 A 加了前置条件，却没在 B 留指针 ⇒ 下一轮照着 B 又登记一笔假债。**改了就回改，一次改完。**

> **回改的适用范围（别改过头）—— 按文档类型判定，不看编号**
>
> | 文档类型 | 要不要同步判据 | 处置 |
> | --- | --- | --- |
> | **生效判据**（`Agent.md` §4 / `data-layer/docs/PRD/`） | **必须同步** | 回改 |
> | **活跃文档**（`Agent.md` · `data-layer/docs/reference/**` · `.codebuddy/commands/**` · 代码文件头） | **必须同步** | 同上 |
> | **过程文档**（`data-layer/docs/plan/**` · `backtest/docs/design/**` · 已完工记录） | **不需要同步** | 见下 |
>
> **🔒 过程文档不需要同步判据**：它记录的是「**当时依据什么做的**」，不是现行判据入口；后面的 AI 不会去看它。
> - 于是：**不回改编号引用**、**不加"改指"注解**、**不加顶部对照声明** —— 全是噪音。
> - 真遇到**已删号的编号**：**直接把那处引用删掉**即可。
> - 确实要留痕的 ⇒ **另写一份实施记录**。
>
> **判据一句话**：**改不改，看它会不会被当入口再查一次。** 会 ⇒ 改；不会（过程/快照）⇒ 不动。

**退役**：标 `已取代 / 已弃用 / 已毕业`，**不删**；删只用于误建，且删必扫引用面。
**改写（形态不合格时）**：推理过程 ⇒ 抽成「判据 + SOP」（过程归实施记录，别删——弯路最贵）；没指导意义 ⇒ 先答「它正确落地时该长什么样」，答得出就**改写成让架构更好的判据**，答不出就**判过期**。

### Step 3 · 立据 —— 新增前三道闸

1. **落笔前 6 判据**：
   🔴 **答卷人是 AI（逐条答），用户决策**：AI 答完**必须把 6 问 + 自己的答卷贴进对话给用户看** → 用户决策（同意 / 不同意）→ 才落笔。
   **只把答卷塞进文档 = 用户没看过**。⚠️ 这一步**没有机器防线**，防线是「贴进对话」这个动作本身。

| # | 判据（问）              | **答不出 ⇒** 的处置                                                                     |
| - | ------------------ | -------------------------------------------------------------------------------- |
| ⓿ | **是否只影响一处？**        | 是 ⇒ **死日记** ⇒ 记 `data-layer/docs/plan/`，**不立判据**                                          |
| ① | **是否推翻了既有约定？**      | 答不出「它凭什么成立」⇒ 那个约定就是**待消灭的对象**（铁律 6）；**"仓里一直这么写"不是依据**                       |
| ② | **能不能不用判据守？** | 类型/键校验 / 结构隔离 / 对账测试能做到 ⇒ **别用判据守，改成代码**。**更该先问：改几行代码就能根治吗？** |
| ③ | **是否有同义 / 近义的判据？** | 有 ⇒ **必合并**；属**判据重复** ⇒ 只钉边界、不合并                                 |
| ④ | **有无违反时的判据？**        | 写不出「怎样发现又回去了」⇒ 它是**没有防线的声明**，不许落笔                                                |
2. **第 ⑤ 问（守护师问）**：**写下它之后，有哪个具体动作会因此改变？** 答不出 ⇒ 不写。
3. **执行面**：先写「这条判据的正确形态」（写不出 = 没理解，**不许落笔**）→ 再查 `Agent.md` §4 + PRD 是否已有；**已有就是正解，一行不写**。

> **⚖️ ROI 判据（用判据守，还是改代码根治？）**
> **判据的永久成本 = 维护 + 对账 + 被误读**（它只增不减）；**改代码的成本 = 一次性**。
> ⇒ **改动半径小且能根治的事，不许拿判据去守** —— 判据：**改一次就能让"误用写不出来"吗？**
> 能（如"某常量只有 5 个消费者" ⇒ 收进 `config.py` 一次性收口）⇒ **去改代码**，判据判过期。
> 不能（跨层 / 需长期防回潮 / 一次改不干净）⇒ 才值得立判据，**并尽快落到代码或测试里**。

**优先级**：**落到代码/测试** > **写进已有条** > **不写**（记录 → `data-layer/docs/plan/`；债 → 「待处理」段） >
**最后才新增，且一轮 ≤3 条**。

## Gotchas

- **闸绿 ≠ 健康**，只等于"它查的那几项没问题"。**工具没拦 ≠ 内容没问题。**
- **误合比不合并更贵** —— 削掉的能力不报错，只在某天变成"某功能静默失效"。
- **判据过期比判据缺失更坏** —— 它稳定产出假债，而假债会让人不再信任何判据。
- **「已毕业」不是「已作废」** —— 判据仍现行，只是载体换成代码/测试。
- **提示 ≠ 拦住** —— 要加检查就真加，别写在文档里装防线。
- **门面行是判据唯一的门面** —— 正文再对，**门面行旧了 = 判据旧了**（AI 只读那一行）。
