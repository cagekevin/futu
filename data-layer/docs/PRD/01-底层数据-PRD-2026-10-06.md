# trading-desk — PRD（需求级契约基线）

> 按 PRD 五步法产出。**本文件是"需求级契约基线"**，写码时逐条对照。
> 配套：`docs/PLAN.md`（项目理念与背景）。**冲突时以本文件为准**（本文件是契约）。
> 状态：第 1 层（骨架）。第 2 层（模块细化）待逐模块追加。

## 一、定位（State 1）

| 维度 | 内容 |
|---|---|
| **做什么** | 一个**数据后端**：自己取数、自己计算、自己组织，**对外提供数据** |
| **给谁用** | **下游**——量化、研究、任何用途的消费方（通过接口/数据拿） |
| **核心价值** | **稳定的数据基础**：装得下任何数据，供得起任何用途，**不拖后腿** |
| **不做什么** | 不做 UI/展示、不做终端、不绑定任何单一用途 |

**能力两层**：
- **底层数据**：K线 / 期权链 / 快照 / 自选 …
- **算好的指标**：GEX / flip / walls / RPS / 行业 / 信号 …

**最高目标（不可违背）**：
> 后端是一个稳定的大数据基础。前端不管做什么都能做。**不拖后腿。**

**不拖后腿验收判据**：
> 明天来个全新用途（研究/回测/新策略），**能不能只靠这个后端做出来、不用回头改后端？**
> 能 ✅ ｜ 不能 ❌（= 设计太窄）

## 二、模块（State 2）

### 依赖实证（事实，非推演 —— 扫 vendor 源码 import 得出）

| 源 | 依赖链 |
|---|---|
| gex | `ingest`(无依赖) → `metrics`(依赖 greeks+rates+ingest) → `report`(依赖 metrics+ingest) |
| futu indicators | `tdx`(无) ← `cd`/`guppy`；`rs`(无) ← `industry` |
| futu 计算 | `tsmom`/`portfolio`/`metrics` 零内部依赖 |

**结论**：依赖方向单一（底层→上层），**无环**。

### 模块列表（5 个）

| # | 模块 | 职责 |
|---|---|---|
| **M1** | 库（store） | 按 (交易日, 标的) 组织数据、读写、时间轴接口 |
| **M2** | 取数（fetch） | 从数据源拉原始数据（CBOE/富途），可换源 |
| **M3** | 计算（engine） | 纯计算：底层数据 → 指标（GEX/RPS/行业/信号） |
| **M4** | 提供（provide） | 对外暴露数据（下游来拿） |
| **M5** | 管线（pipeline） | 编排：取数 → 计算 → 入库 |

### 依赖方向（写死，不可逆）

```
M5 管线  →  M2、M3、M1
M4 提供  →  M1
M3 计算  →  （零依赖）
M2 取数  →  外部接口（不依赖 M1/M3/M4）
M1 库    →  （零依赖）
```

**额外检查结论**：
- 模块**互不重叠**（各有单一职责）
- ⚠️ 唯一潜在重叠：**M4 与 M1**（都"取数据"）
  → **划分**：M1 = 内部读写；M4 = 对外接口。**若 M4 沦为 M1 的薄壳 → 并回 M1（不造假模块）。**

## 三、陷阱（State 3）

| # | 陷阱 | 翻车形态 |
|---|---|---|
| **T1** | **入库/取数竞态** —— 数据是半成品 | 管线跑到一半，下游取到"残的一天" |
| **T2** | **一套数据两处存** —— SSOT 破坏 | 底层更新了、指标没跟，下游取到矛盾的两个数 |
| **T3** | **提供接口随用途长歪** | 堆满"某用途专用"字段 → 后端成缝合层 → 拖后腿 |

## 四、约束（State 4）

### 跨模块约束（锚定后续一切细化）

| # | 约束 | 可验证标准 |
|---|---|---|
| **X1** | **数据只有一份（SSOT）** | 指标**只存怎么算（依赖的参数/标的/日期），不冗余存底层值**；取值现算或只读底层 |
| **X2** | **入库是原子的** | 某天某标数据，要么**完整可读**，要么**不可读**（不做"读到一半"） |
| **X3** | **依赖方向不可逆** | M5→M2/M3/M1；M4→M1；M3 零依赖；M1 零依赖。**违反即报** |
| **X4** | **接口不知道来源** | M4 接口与 M1 键里，**不出现数据源名**（cboe/futu…） |
| **X5** | **反掩盖 P1–P6 全局生效** | 缺/错/不一致 → 报，不降级 |

### 各模块核心约束

| 模块 | 约束 | 可验证标准 |
|---|---|---|
| **M1 库** | 键 = (交易日, 标的, 数据项)；读写原子 | 键不含源名；写入要么全成要么全不写 |
| **M2 取数** | 只取数，不计算；换源只动本模块 | 无 `metrics`/`gex` 类计算；换源不改 M1/M3/M4 |
| **M3 计算** | 纯计算，不碰 IO | import 无 `requests`/`open`/`pandas.read_*` |
| **M4 提供** | 不绑定用途；沦为薄壳则并回 M1 | 参数无"用途"语义；仅转发则合并 |
| **M5 管线** | 只编排，不实现能力 | 无业务算法，只"调 M2/M3/M1" |

### 约束 → 跨模块约束的支撑关系

- M1 键不含源名 → **X4**
- M2 只取数 → **X3**
- 入库原子 → **X2**
- M4 不绑定用途 → **最高目标"供得起任何用途"**
- M3 纯计算 → **X1**（可随时重算，不冗余存）

## 五、第 2 层：模块细化（待逐模块追加）

> 每次只细化一个模块，走五步法，确认后追加到本节。

### M1 库（store）—— 已细化

**State 1 边界**：把数据按 (交易日, 标的, 数据项) 组织起来，提供**原子的读写**。
校验：与全局定位、X1–X4 无冲突。

**State 2 结构**（4 个子功能）：

| 子功能 | 职责 |
|---|---|
| M1.1 键（Key） | 定义 (交易日, 标的, 数据项) 的表示与规范化 |
| M1.2 存储（Storage） | 数据物理落在哪、怎么存 |
| M1.3 写入（Write） | 原子写入（全成/全不写） |
| M1.4 读取（Read） | 时间轴接口：days/symbols/items/get/series |

**State 3 陷阱**：

| # | 陷阱 | 翻车形态 |
|---|---|---|
| M1-A | 键不规范 | `2026-10-06` vs `20261006` 两套 → 取不到 |
| M1-B | 非原子写入 | 写一半崩 → 留下半个文件 → 下游读残数据（T1） |
| M1-C | 数据项无规范 | `gex_flip` vs `flip` 同物异名 |
| M1-D | 键缺失时"取最新" | 缺 10-06 → 自动返回 10-05（违反 P6） |

**State 4 约束**：

| # | 约束 | 可验证标准 | 支撑 |
|---|---|---|---|
| **K1** | **键 = 三元组（交易日, 标的, 数据项）**，规范化：<br>交易日 `YYYY-MM-DD`；标的=纯代码（无源名/前缀）；数据项=受控清单名 | 同一(日,标的)只有一个键表示；键里**无** `US.`/`cboe`/`futu` | **X4** |
| **K2** | **写入原子** —— 要么完整可读，要么不存在 | 临时文件 + 原子 rename；中断不留半个文件 | **X2** |
| **K3** | **数据项是受控清单** —— 有明确名字表，不许随意起名 | 每项在清单里注册；未注册名 → 报错 | **X1** |
| **K4** | **读不产生写、读不降级** —— 缺失就是缺失 | `get` 缺失返回"无"，**绝不**返回邻近日期；读取不修改任何东西 | **P6** |
| **K5** | **M1 零依赖** | `store/` import 里无 `fetch`/`engine`/`provide` | **X3** |

**验证标准（可跑）**：
```bash
# K1：写两次同一天同标的 → 只有一个键
# K2：写入中途 kill → 磁盘上没有半截文件
# K3：用未注册的数据项名写 → 报错
# K4：取不存在的日期 → 返回"无"，不返回别的日期
# K5：grep store/ 的 import → 无 fetch/engine/provide
```

### M2 取数（fetch）—— 已细化

**State 1 边界**：从各数据源拉原始数据，**归一化成统一结构**，交给 M1 存。
校验：与 X3/X4、"可换源"无冲突。

**State 2 结构**（3 个子功能）：

| 子功能 | 职责 |
|---|---|
| M2.1 源适配器（Source） | 每个数据源一个适配器（CBOE / 富途） |
| M2.2 归一化（Normalize） | 各源原始格式 → 统一结构 |
| M2.3 参数（Request） | 统一请求参数（标的/日期/类型） |

**State 3 陷阱**：

| # | 陷阱 | 翻车形态 |
|---|---|---|
| M2-A | 源名泄漏到上游 | 返回数据带 `cboe_` 前缀 → 违反 X4 |
| M2-B | 各源格式不一 | `open_interest` vs `option_open_interest` → 上游分情况 |
| M2-C | 假可换源 | 写了配置但代码写死（S/R 的 A4 教训） |
| M2-D | 失败静默 | 拉取失败返回空/None，上游以为"没数据"（违反 P4/P6） |

**State 4 约束**：

| # | 约束 | 可验证标准 | 支撑 |
|---|---|---|---|
| **F1** | 数据源是 M2 内部实现 | 返回结构无源名；M2 之外无 `cboe`/`futu` 字样 | X4 |
| **F2** | **出口归一化**：通用字段统一命名 + 源特有原样保留 | 通用字段两源一致；源特有字段集中在独立字段里，**不以源名当键** | X4 |
| **F3** | 换源只动 M2 | 加新源只新增 `fetch/` 文件 | 铁律5 |
| **F4** | 取数失败必报 | 失败抛错（含源/标的/原因） | P4/P6 |
| **F5** | 原始数据也保留 | 期权链每合约都在 | 最高目标 |

**F2 细化**：出口 = `{ 通用字段…, extra: {…源特有…} }`
- 通用：`symbol / expiry / strike / cp / bid / ask / open_interest / volume …`
- `extra`：源特有什么放什么，键名**不代表源**（上游知"extra 未归一，用前要看"）

**验证标准**：
```bash
# F1：grep M2 之外的代码 → 无 cboe/futu 字样
# F2：CBOE 与富途的"K线"出口字段名一致
# F3：加一个新源（如 tradier.py），不改其它模块
# F4：断网跑取数 → 抛错，不静默返回空
# F5：取到的期权链含全部合约
```

### M3 计算（engine）—— 已细化

**State 1 边界**：纯计算——拿底层数据，算出指标，返回（**不写回、不读盘**）。
校验：与 X1/X3 无冲突。指标存不存 → 见 G6。

**State 2 结构**（3 个子功能）：

| 子功能 | 职责 |
|---|---|
| M3.1 希腊值（greeks） | BS 纯函数（价格/希腊值/IV） |
| M3.2 指标（indicators） | GEX / flip / walls / RPS / 行业 / 信号 各自纯函数 |
| M3.3 契约（IO Contract） | 每个指标的输入/输出结构（不碰 IO） |

**State 3 陷阱**：

| # | 陷阱 | 翻车形态 |
|---|---|---|
| M3-A | 纯计算里混进 IO | 指标偷偷读文件/联网 → 不可测、不可重算 |
| M3-B | "算"和"存"耦合 | 算时顺手存 → 违反 X1（两处存） |
| M3-C | 指标依赖"当前时刻" | 用 `now()` 而非传入日期 → 不可复现 |
| M3-D | 指标不自证 | 不记"用的哪份数据/何时算的" → 违反 P3 |

**State 4 约束**：

| # | 约束 | 可验证标准 | 支撑 |
|---|---|---|---|
| **G1** | 纯计算，零 IO | `engine/` import 无 `requests`/`open`/`read_*` | X3 |
| **G2** | 只算不存 | `engine/` 里无写文件 | X1 |
| **G3** | 时刻显式传入 | 需"当前时刻"的函数都以参数接收 | P3 |
| **G4** | 输出自带来源 | 返回值含 `source_key` + `computed_at` | P3 |
| **G5** | 可独立重算 | 同一输入 + 同一参数 → 结果逐位一致 | X1 |
| **G6** | **指标版本校验** | 存指标记底层版本 V；取值时当前版本 ≠ V → **报错**。**无自动重算、无部分失效、无回退** | X1 + X2 |

**G6 语义（只两态）**：
```
对得上 → 返回指标
对不上 → 报错「指标已失效（依赖 {source_key} 版本 {V}，现为 {V'}），请重算」
```

**验证标准**：
```bash
# G6-a：底层不变 → 取指标成功
# G6-b：底层变了 → 取指标报错（不返回旧值、不返回新值）
```

### M4 提供（provide）—— 已细化

**State 1 边界**：对外暴露数据（下游来拿）—— 把"本地怎么存"翻译成"下游怎么拿"。
校验：与 X4、最高目标无冲突。

**State 2 结构**（M4 相对 M1 的实质职责）：

| 职责 | M1 有吗 |
|---|---|
| A. 转发读取 | ❌ M1 已有 → **薄壳信号** |
| B. 批量/聚合查询 | ✅ M1 没有 |
| C. 格式转换 | ⚠️ 看差异 |
| D. 跨进程/网络访问 | ✅ M1 没有 |

**State 3 陷阱**：

| # | 陷阱 | 翻车形态 |
|---|---|---|
| M4-A | 沦为薄壳 | 只是 `return m1.get(...)` → 假模块（铁律5） |
| M4-B | 为用途定制 | 接口出现"给某用途的字段" → 违反最高目标（T3） |
| M4-C | 泄漏存储细节 | 下游得知道"文件在哪/格式如何" → 违反 X4 |

**State 4 约束**：

> **裁决 D2：M4 保留**（理由：M1 是"同进程内库读写"，M4 是"对外提供"，
> 两者**变化速率不同** —— 内部存储格式会变、对外契约要稳。若合并，
> 将来"内部改存储"会波及所有下游 → **真缝隙**）。
> ⚠️ 但写死：**若实际沦为薄壳，则并回 M1**（不搞教条）。

| # | 约束 | 可验证标准 | 支撑 |
|---|---|---|---|
| **P1** | 不绑定用途 | 接口参数/返回**无"用途"语义**（无"择时专用"字段） | 最高目标 |
| **P2** | 不泄漏存储细节 | 下游**不知道**文件路径/格式/源名 | X4 |
| **P3** | 薄壳即合并 | 若仅转发 M1 的 `get` → **判薄壳 → 并回 M1** | 铁律5 |
| **P4** | 对外契约稳定 | 内部存储格式变化**不改对外接口** | 最高目标 |

**验证标准**：
```bash
# P1：接口参数/返回里无"用途"字样
# P2：下游调用只需 (交易日,标的,数据项)，不需知道路径/格式
# P3：若 M4 代码只是转发 m1.get → 触发合并（人工判）
# P4：改内部存储格式 → 对外接口签名不变
```

### M5 管线（pipeline）—— 已细化

**State 1 边界**：编排一天的数据生产——定交易日 → 调 M2 取数 → 调 M3 计算 → 调 M1 入库。
校验：与 X3（依赖方向）、"只编排"无冲突。

**State 2 结构**（3 个子功能）：

| 子功能 | 职责 |
|---|---|
| M5.1 定日期（Day） | 确定交易日 D（美东），**不是本机日期** |
| M5.2 编排（Orchestrate） | 按顺序调 M2 → M3 → M1 |
| M5.3 校验（Verify） | 每步后校验（返回码/日期 == D），失败即停 |

**State 3 陷阱**：

| # | 陷阱 | 翻车形态 |
|---|---|---|
| M5-A | 用本机日期当交易日 | 在香港跑美股 → 记错一天（gex 踩过） |
| M5-B | 某步失败仍继续 | 取数失败还去计算 → 算出垃圾 |
| M5-C | 编排里藏业务逻辑 | 管线里写"如果 GEX>0 就…" → 违反"只编排" |
| M5-D | 半天数据入库 | 取到一半就入库 → T1 竞态（K2 原子写的编排侧配合） |

**State 4 约束**：

| # | 约束 | 可验证标准 | 支撑 |
|---|---|---|---|
| **L1** | **交易日 = 美东日期**，非本机日期 | 香港白天跑，交易日记为美股当天 | 防 M5-A |
| **L2** | **任一步失败 → 立即停**，报错不继续 | 取数失败 → 不进入计算；附失败步/原因 | **P4/P6** |
| **L3** | **只编排，不实现能力** | 管线里无业务算法，只有"调 M2/M3/M1" | **X3** |
| **L4** | **一天 = 一个原子单位** | 中途失败 → 库里当天数据**不残**（配合 K2） | **X2** |

**验证标准**：
```bash
# L1：模拟非美东时区跑 → 交易日记为美东日
# L2：故意让取数失败 → 管线停，不进入计算
# L3：grep pipeline.py → 无算法实现，只有调用
# L4：入库中途 kill → 库里当天无残数据
```

## 六、地基级固化（定死 vs 留白）

> 判据 = **可逆性**（铁律 6）：不可逆/高代价 → **定死**；可逆 → **留白**（写码时定，但受约束管）。

| 内容 | 可逆性 | 决定 |
|---|---|---|
| M1 数据项命名规范 | 🔴 不可逆（下游用了/数据存了） | **定死** |
| M1 存储格式 / 目录布局 | 🔴 数据落了盘 | **定死** |
| M1 键的表示 | 🔴 同上 | **定死** |
| M2 归一化后通用字段清单 | 🟠 出口契约 | **定死** |
| M2 具体源适配器实现 | 🟢 内部可换 | 留白 |
| M3 指标命名规范（同 M1） | 🔴 被引用即固定 | **定死** |
| M3 指标函数签名 | 🟢 内部 | 留白 |
| M4 接口形态 | 🟠 对外契约 | **定死"函数级"**，签名留白 |
| M5 命令行入口 | 🟢 可改 | 留白 |

### 6.1 数据项 / 指标 命名规范（**定死**）

**格式**：`<主体>_<属性>`，全小写蛇形（snake_case）。

**三条规矩**：
1. **不含源名** —— 不用 `cboe_gex` / `futu_rps`
2. **不含用途名** —— 不用 `timing_gex` / `stock_rps`
3. **集中注册** —— 清单在一处，未注册的名 → 报错（承 K3）

**"准确优先"细则**：
