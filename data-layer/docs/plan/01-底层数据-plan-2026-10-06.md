# trading-desk — PLAN

> **独立、自包含的数据后端。** 不引用、不依赖任何外部项目。
> 老项目的能力源码已复制到 `vendor/` 作参照，本系统把它们**重新长成自己的器官**。
>
> ★ **接手入口见顶层 [`Agent.md`](../../../Agent.md)**（先读什么 / 能力在哪查 / 什么绝对不能做）。

---

## ★★★ 最高目标（凌驾于一切）

> **后端是一个稳定的大数据基础。前端不管做什么都能做。**
> 不管是**量化、研究、还是任何事** —— 都建立在**稳定的数据基础上**。
> **这个数据后端，不要拖后腿。**

**四条硬要求**：

| 要求 | 意味着 |
|---|---|
| **稳定** | 数据**只有一份**（SSOT），不各处置一份、不会对不上 |
| **基础** | 它**不依赖任何下游**；下游全依赖它。**它是最底层** |
| **装得下任何数据** | (交易日, 标的) → 数据项，**无限扩展** |
| **供得起任何用途** | **提供底层数据**（不是"为某个用途算好的"）+ 算好的指标 |

**⚠️ 最关键**：因为要支持"任何事"，**不能只为某一个用途设计**。
若只提供"某个用途要的字段"，就**只能干那件事** —— **那它就拖后腿了。**

### ★ 不拖后腿的验收判据（写死）

> **明天来个全新用途**（研究 / 回测 / 新策略），
> **能不能只靠这个后端做出来，而不用回头改后端？**
> **能 → 不拖后腿 ✅ ｜ 不能 → 设计太窄 ❌**

## ★ 第零原则：反掩盖清单（仅次于最高目标）

> 铁律。**核心一句：错就是错，错必须显形。**
> （这是"稳定"的底层保证：**被掩盖的错误 = 不稳定的数据**。）

| # | 原则 |
|---|---|
| **P1** | **禁止默认值兜底**。缺字段/类型错/空值 → **报错**。唯一允许的 `None` = 源自己给的 null，且**必须显形**。 |
| **P2** | **禁止"容忍未知结构"**。字段清单写死；多一个/少一个键 → **当场报错**。 |
| **P3** | **数据自证**。每个数带来源时刻；口径指纹变了 → 报。 |
| **P4** | **校验"真取到"，不看"文件在不在"**。接口返回码非成功 / 内容日期与请求不符 → 报。 |
| **P5** | **异常值必须显形**。NaN / 符号矛盾 / 日期倒挂 → 报警 + 显示原值，不修正不丢弃。**展开见附录 A。** |
| **P6** | **错误就是错误，不许降级**。缺/错/不一致 → 停下报清，不给"看似可用"的错屏。 |

## 一、这个系统是什么

**一句话**：**一个稳定的数据后端**。自己取数、自己计算、自己组织；**对外提供数据**；
下游（量化 / 研究 / 任何用途）来拿就行。

**它不是**：不是展示壳、不是筛选器、**不是终端/UI**。

**它提供两层**（"不拖后腿"的关键）：

| 层 | 提供什么 |
|---|---|
| **底层数据** | K线 / 期权链 / 快照 / 自选 …（**任何用途都能从底层自建**） |
| **算好的指标** | GEX / flip / walls / RPS / 行业 / 信号 …（方便直接用，底层也在） |

**边界**：老项目不归本系统管；本系统自己跑自己的。

## 二、主线：先把"数据基础"立起来

> **主线不是"做择时、做择股"（那是功能顺序），是"立数据基础"（那是地基顺序）。**
> **"择时"只是验证地基能用的第一个用例。**

就像盖楼：**先打地基、立柱、浇筑，最后才把第一个房间装出来** —— 而不是"先装择时这个房间"。

```
1. 骨架   时间轴：(交易日, 标的) 的库        ← 地基本身
2. 取数   把各种原始数据灌进来（可换源）
3. 存储   数据怎么在库里组织
4. 计算   指标怎么从底层数据算出来（纯计算）
5. 提供   怎么对外拿
────────────────────────────────
6. 用例   用"大盘择时"验证整条链能跑通      ← 验证，不是主线
```

**优先级**：1–5 是**地基**（一次做对）；6 是**第一个用例**（证明地基可用）。

## 三、地基本身：时间轴 + (交易日, 标的) → 数据项

### 3.1 一切数据 = (交易日, 标的, 数据项)

- **标的** = **任何代码**。股票 / 期货 / ETF / 加密 / 外汇 / 指数 —— **一律平等**（期货也是代码）。
  **没有"大盘数据 vs 个股数据"，只有"标的不同"。**
- **数据项** = **可无限扩展**。今天是价格/GEX/RPS，明天加"资金流"……**地基不用改**。

```
        SPX   AAPL   ES    BTC   ...
10-06   ·     ·      ·     ·
10-05   ·     ·      ·     ·
  ↑ 交易日（时间轴）    ↑ 标的（任何代码）
```

### 3.2 底层数据要装什么（从老项目取数能力倒推）

| 底层数据 | 来自哪个取数能力 | 说明 |
|---|---|---|
| **K线** | futu `kline.mjs` | 日/周/分钟 OHLCV |
| **期权链** | gex `ingest.py`（CBOE） | 每个合约的 bid/ask/IV/OI/volume |
| **全市场快照** | futu `screen_v2.py` / `universe.py` | 几千只的价/市值/涨幅/行业 |
| **自选清单** | futu `watchlist.mjs` | 分组 → 标的 |
| **基本面** | futu `fundamentals.mjs` | PE/PB/EPS… |
| **指数/利率** | gex `pricehist.py` / `rates.py` | 指数收盘、无风险利率 |
| **期权流** | gex `flowtape.py` | 逐笔（可选） |

**算好的指标**（从底层数据算）：GEX / flip / walls / RPS / 行业状态 / CD / 顾比 …

### 3.3 库的接口（浅）

```python
# 库（回答"有什么"）
Axis.days()                      # 有哪些交易日
Axis.symbols(d)                  # 某天有哪些标的
Axis.items(d, sym)               # 某天某标的有哪些数据项
Axis.get(d, sym, item)           # 取某天某标的的某项数据
Axis.series(sym, item)           # 某项数据的连续序列（跨日，供时间序列）
```

**规矩**：只描述"有什么"，不判断好坏；**缺就是缺**，不"取最新"、不降级（P6）。
**上层永远不需要**知道数据怎么来的、从哪个源取的 —— 那是 `fetch/` 的实现细节。

### 3.4 验收判据

> **上游代码里绝不允许出现**：数据源名字 / 原始接口字段名 / 原始 JSON 的键 /
> 字符串键 / `None` 判断。出现任一 = 地基漏水。

## 四、分层

```
┌─────────────────────────────────────────────────────────────┐
│  provide/    提供：对外暴露数据（下游来拿）                    │
├─────────────────────────────────────────────────────────────┤
│  engine/     计算：GEX / RPS / 行业 / 信号（纯计算，不碰 IO）  │
├─────────────────────────────────────────────────────────────┤
│  fetch/      取数：拉原始数据、落盘（可换源，只动这里）         │
├─────────────────────────────────────────────────────────────┤
│  store/      库：按 (交易日, 标的) 组织，挂数据项              │
└─────────────────────────────────────────────────────────────┘
```

**判据（写死）**：
- `fetch/` 只取数，**不做计算**；**换源只动这里**
- `engine/` **纯计算，不碰 IO**
- `store/` 只管"某天某标有什么数据"
- `provide/` 只提供数据，**不做展示**

## 六、运行管线

```
pipeline.py（产出数据）
  │
  ├─ ① 定交易日 D（美东今天）
  │
  ├─ ② 取数    fetch/sources/cboe_options_source.py  → 期权链
```

### S9.2 关键实测（全部写进知识文档）

- **ktype 两套编号不同**：OpenD 是字符串 `K_240M`；REST 是数字（14=120分，**无 240 分**）。
- **OpenD 的 `request_history_kline` 忽略 `end`、只认 `start`**；REST 相反（`end`+`num` 往前翻）。
- **protobuf 必须 < 5**（否则 `get_stock_screen` 报 `FieldDescriptor.label`）；已锁 `requirements.txt`。
- **OpenD 分钟线历史深度有限**（240M 实测到 2026-09-01）→ 长历史走 REST。
- **美股指数 K线无权限**（`暂不支持美股指数`）。

| 能力 | 实现 |
|---|---|
| **时区统一** | 新增 `trading_time.py`：`to_unix_seconds`（毫秒 / ISO / naive-ET → **Unix 秒**）、`trading_day`（→ 美东日）、`et_datetime`。两通道 K线 `time_key` 归一；落库时间戳（`feed_timestamp` / `fetched_at` / `computed_at`）统一为 Unix 秒 |

多品种对齐**全错**。`trading_time` 把两者收敛到**同一种表示**。

### S10.2 职责边界（★ 关键结论）

- **停牌**的数据层职责 = **不造假**（存储 / 读取不补），**不是**"对齐"。
- **对齐**依赖"品种集合"（**下游参数**）→ 属**对外提供**层，是**纯算子 / 按需 / 不存储 / 不强制**。
- 因此 `engine/time_alignment.py` 定位为**纯计算算子**（engine 零 IO），**不接存储、不做默认**。

## 八·补4、S12 时间戳单位显式化 + 口径文档（2026-10-06 追加）

> 来源：回测设计文档（`backtest/docs/design/`）新增 **D7–D11**（时间戳量级 / 复权口径）。
> 经逐条判断：**真正落在数据层、且原来会静默出错的，只有 D7**；D8–D11 属回测层（复权换算 / 口径选择）。

### S12.1 做了什么

| 项 | 做法 |
|---|---|
| **D7 时间戳量级校验** | `trading_time.to_unix_seconds` **去掉"按数值大小猜单位"**（旧 `abs>=1e11→毫秒` 会把 `秒÷1000` 静默当秒 → 1970）。改为：**数字时间戳必须显式 `unit="s"｜"ms"`**（不猜）；自描述输入（`datetime` / ISO）不给 unit。一律做**量级校验**：落在 `[1980, 2100)` 之外 → **报错**（承 P6，不静默修） |
| **调用方显式声明** | REST 源 `_bar_row` 传 `unit="ms"`（源事实）；`pipeline.run_kline` 回读库里 `time_key` 传 `unit="s"` |
| **口径文档** | `Agent.md` §4.4 写明：① 统一到**秒** ⇒ 不含逐笔（tick 另论）；② **回测用 hfq（因果）、qfq 非因果**；③ 数据层只存 raw + 因子、**不设默认口径** |

### S12.2 为什么"不猜单位"

单位是**源的事实**（REST 是毫秒、OpenD 是字符串），应由**源适配器显式声明**；公共函数只**校验**。
靠数值大小猜 = 脆弱，正是 D7 的根因。

### S12.3 验收

- `tests/test_trading_time.py` 新增：数字不给 unit → 报错；越界（1970 / 远未来 / 秒误标 ms）→ 报错；非法 unit → 报错。
- 受影响测试文件（时区 / 管线 / 计算 / 提供 / 取数 / 富途源）全绿。

## 八·补5、S13 复权因子资料 + 唯一实现（2026-10-06 追加）

> 来源：回测设计文档 §0.2 / §11 把「复权价」判给数据层（**存原料 + 唯一实现**）。
> 数据层现在只有 raw + 因子，**没有唯一实现** —— 本次先**补资料**，实现**待验证后落**。

### S13.1 资料（已落）

- 新增 `docs/reference/futu/adjustment-factor.md`（复权因子专章）：
  - **官方公式**（`openapi.futunn.com`）：`复权价 = 不复权价 × A + B`（前 / 后各一组）。
  - **实测**：A/B 是**每除权日一条的单日因子**（非累计）；拆股 A = ratio（前）/ 1/ratio（后）；
    派现 前 A = 1 − 派现/收盘、后 A = 1 / B = +派现。
  - **口径**：qfq **含未来**（禁回测）；hfq **因果**（回测用）；`mode` 显式、无默认。
- 同步：`README.md`（分册 4→5）、`opend.md`、`Agent.md` §2 / §4.4。

### S13.2 对拍验证（**已做**，2026-10-06）

脚本 `tests/verify_adjustment_formula.py <SYMBOL>`（拿富途自己的复权 K线逐根比）：

| 口径 | 公式 | 结果 |
|---|---|---|
| **前复权** | `qfq(t) = raw(t) × ∏_{d>t} forward_A(d)` | ✅ **确认**（NFLX 逐根 **0.000000%**；AAPL 0.017% = 量化噪声） |
| **后复权（仅拆股）** | `hfq(t) = raw(t) × ∏_{d≤t} backward_A(d)` | ✅ 确认（NFLX 逐根一致） |
| **后复权（含派现）** | ？ | ❌ 未确认（AAPL 差 ~3%，5 个候选全不对） |

- 边界严格：前 `d > t` / 后 `d ≤ t`（前复权用 `d >= t` 差 90%）。
- 库里因子 = 富途现拉（AAPL 都 62 条）→ **不是缺数据，是公式**。

### S13.3 判定（**暂不实现**）

- **hfq**：结构已找到（`hfq = raw × ∏_{d≤t}A_b + D`，D 是**加法**分红项、**除权日之间恒定**），
  但 **D 的精确形式没定**；且**富途自己的 hfq 不自洽**（拆股日差 0.12%，TR 口径本应连续）
  → **没有可靠基准** → **做不了**（硬上就是猜）。
- **qfq**：公式已逐根确认，但**无消费方**（回测要 hfq）→ **不实现**（不为不存在的消费方造接口）。
- ⇒ **复权继续挂账**；手册 §11 自己写"本文不碰"，**不挡手册跑通**。
- 验证脚本留在 `tests/verify_adjustment_formula.py <SYMBOL>`（将来接着挖）。

## 附录 A：从 S/R 项目学到的（`Detect_support_and_resistance_levels`）

> 读其 `app.py` / `config.py` / `src/sr_engine.py` / `src/local_data_loader.py` 后提炼。
> 它整体是"好的数据诚实性 + 差的架构可换源"。

### ✅ 学（3 条）

**A1. 降级必须挂回数据本身（P5 展开）**
缺因子时**不静默降级**：照常返回数据，但把降级标记挂在数据上，**必须显形**。
它的原则：
> 回测缺因子直接报错（宁可不跑）；界面缺因子仍展示，但必须让用户看见这个事实。

→ **本系统**：降级标记**随数据返回**。
⚠️ **但不用 `df.attrs`**（pandas 操作后会丢）—— 用**结构化字段**。

**A2. 批量视图也要显形，不能只在单条视图告警（P5 展开）**
> "批量里大部分标的可能缺因子而降级，如果只在详情页告警，批量表格就会误导用户。"

→ **本系统**：某字段"部分数据有问题"时，**每一行都带这个状态**。

**A3. 入口归一化成统一出口（fetch 层职责）**
无论原始格式如何，**出口固定结构**，且处理可选字段缺失。

→ **本系统**：`fetch/` 出口统一结构，**怪东西在入口洗掉**。

### ⚠️ 弃（2 条）

**A4. `DATA_SOURCE = "baostock"` 是假开关** —— config 写了但 loader 没读。
→ **本系统**：换源要么**真能换**，要么**不写那个配置项**（铁律 5）。

**A5. `df.attrs` 传状态 —— 载体脆**（pandas 操作后不保证保留）。
→ **本系统**：学 A1 的精神，**换稳载体**。

### 一句话

> S/R 在**"数据字段的诚实性"上做得好**（与 P1–P6 同频）；
> 在**"架构可换源"上是假的**。**学它的诚实，弃它的假开关。**
